## 📄 解説するコード（293〜360 行目・抜粋）

```javascript
// ---------- モーダル ----------
function showWho() {
  document.getElementById("modal").innerHTML = `<div class="modal"><div class="card"><h2>あなたは誰？</h2>
    <div class="who">${S.settings.members.map(m => `<button data-me="${esc(m)}">${esc(m)}</button>`).join("")}</div>
    <p class="mini">この端末に記憶されます。右上からいつでも変更できます。</p></div></div>`;
}
function showSettings() { /* タイトル・本番の日付・メンバー名を入力するフォームを出す */ }
const closeModal = () => document.getElementById("modal").innerHTML = "";

// ---------- イベント ----------
document.addEventListener("click", e => {
  const z = e.target.closest("[data-zoom]");
  if (z) { document.getElementById("modal").innerHTML = `<div class="modal lightbox" data-act="close"><img src="${z.src}" alt=""></div>`; return; }
  if (e.target.closest(".lightbox")) return closeModal();
  const t = e.target.closest("button,input[type=checkbox]"); if (!t) return;
  const d = t.dataset;
  if (d.tab) { S.tab = d.tab; lsSet("pu-tab", d.tab); render(); scrollTo(0, 0); }
  else if (t.id === "meBtn") showWho();
  else if (d.me) { S.me = d.me; lsSet("pu-me", d.me); closeModal(); render(); }
  else if (d.act === "settings") showSettings();
  else if (d.act === "close") closeModal();
  else if (d.act === "clearPhoto") { S.ideaPhoto = null; render(); }
  else if (d.filter) { S.filter = d.filter; render(); }
  else if (d.cycle) { const x = S.tasks.find(k => k.id === d.cycle); if (x) store.update("tasks", x.id, { status: { todo: "doing", doing: "done", done: "todo" }[x.status] || "todo" }); }
  else if (d.toggle) { const x = S.milestones.find(k => k.id === d.toggle); if (x) store.update("milestones", x.id, { done: !x.done }); }
  else if (d.like) {
    if (!S.me) return showWho();
    const x = S.ideas.find(k => k.id === d.like); if (!x) return;
    const likes = x.likes || [];
    store.update("ideas", x.id, { likes: likes.includes(S.me) ? likes.filter(n => n !== S.me) : [...likes, S.me] });
  }
  else if (d.del) { const [col, id] = d.del.split(":"); if (confirm("削除しますか？")) store.remove(col, id); }
});

document.addEventListener("submit", e => {
  const f = e.target.closest("form[data-form]"); if (!f) return;
  e.preventDefault();
  const v = Object.fromEntries(new FormData(f));
  const col = f.dataset.form;
  if (col === "settings") { /* 設定を保存して閉じる */ return; }
  if (!S.me) return showWho();
  const author = S.me;
  if (col === "tasks") store.add(col, { title: v.title.trim(), assignee: v.assignee, due: v.due, status: "todo", author });
  if (col === "milestones") store.add(col, { title: v.title.trim(), date: v.date, done: false, author });
  if (col === "logs") store.add(col, { text: v.text.trim(), date: v.date || today(), author });
  if (col === "ideas") { /* 文字か写真が必要。失敗したら alert */ }
  if (col === "expenses") store.add(col, { item: v.item.trim(), amount: +v.amount, paidBy: v.paidBy, date: v.date || today(), author });
  pending = false; render();
});
```

## 🧭 ひとことで言うと

**JavaScript** で書かれた、**ボタンを押した・フォームを送信した、という操作（イベント）を受け止めて、データを変える** 部分です。ボタン 1 つ 1 つに処理を付けるのではなく、**ページ全体で 1 か所だけ** 受け止めているのが特徴です。

## 🗺️ 全体の流れ

**クリックされたとき**
1. ページ全体（`document`）でクリックを受け取る
2. 押された場所から一番近いボタンを探す（`closest`）
3. ボタンの data 属性（`data-tab`・`data-cycle` など）を見て、何をするか決める
4. 画面の切り替えなら `S` を変えて `render()`、データの変更なら `store.update` などを呼ぶ

**フォームが送信されたとき**
1. ページの再読み込みを止める（`preventDefault`）
2. フォームの入力値をまとめて取り出す
3. `data-form` の値（tasks など）に応じて `store.add` で保存する

## 🔍 ブロックごとの解説

### イベント委任：1 か所でまとめて受け止める

```javascript
document.addEventListener("click", e => { ... });
```

このアプリは `render()` のたびに画面を作り直すので、ボタンも毎回新しくなります。ボタンごとに処理を付けると、描き直すたびに付け直しが必要です。
そこで、**ページ全体（document）に 1 つだけ** 処理を付け、クリックが「泡のように上に伝わってくる」性質（バブリング）を利用して受け止めています。これを **イベント委任** と呼びます。

### closest と dataset：何が押されたかを知る

```javascript
const t = e.target.closest("button,input[type=checkbox]");
const d = t.dataset;
```

- `e.target`：実際にクリックされた要素（ボタンの中のアイコンの場合もある）
- `closest(...)`：そこから外側へたどって、一番近いボタン（かチェックボックス）を探す
- `dataset`：`data-tab="tasks"` のような data 属性を `d.tab` で読めるようにしたもの

5 ページ目で描いたボタンには、それぞれ data 属性が付いていました。

| data 属性 | 押したときにすること |
|---|---|
| `data-tab` | タブを切り替える（最後のタブとして端末に記憶） |
| `data-me` | 「あなたは誰？」で名前を選ぶ |
| `data-act` | 設定を開く・閉じる・写真を取り消す |
| `data-filter` | タスクを担当者で絞り込む |
| `data-cycle` | タスクの状態を 未着手 → 進行中 → 完了 → 未着手 と回す |
| `data-toggle` | 予定の完了チェック |
| `data-like` | いいねを付ける・外す |
| `data-del` | 確認してから削除（`"tasks:abc123"` を `:` で分けて種類と ID を取り出す） |

### 状態を回す：対応表を使ったトリック

```javascript
{ todo: "doing", doing: "done", done: "todo" }[x.status] || "todo"
```

「今が todo なら次は doing」という **対応表をその場で作って、今の状態で引く** 書き方です。if を 3 つ並べるより短く書けます。

### いいねの付け外し

```javascript
likes.includes(S.me) ? likes.filter(n => n !== S.me) : [...likes, S.me]
```

自分の名前が入っていれば取り除き（いいね解除）、入っていなければ末尾に足す（いいね）。どちらも **新しい配列を作って** 保存しています。

### フォームの送信

```javascript
e.preventDefault();
const v = Object.fromEntries(new FormData(f));
```

- `preventDefault()`：フォームを送信すると、普通はページが再読み込みされる。それを止めて JavaScript で処理する
- `new FormData(f)`：フォームの入力欄を `name` ごとに集める
- `Object.fromEntries(...)`：`{ title: "会場を探す", assignee: "メンバーA", due: "2027-01-10" }` のようなオブジェクトにする

`<input name="title">` の `name` が、そのまま `v.title` の名前になります。

### 名前を選んでいないと書き込めない

```javascript
if (!S.me) return showWho();
const author = S.me;
```

誰が書いたかを `author` として一緒に保存するため、名前が未選択なら先に「あなたは誰？」を出します。

### 変更したあと、画面はいつ変わる？

`store.update(...)` を呼んでも、ここでは `render()` を呼んでいません（タブの切り替えなどは除く）。
**データが変わると Firebase から知らせが届き、そこで描き直される** からです（3 ページ目の `onSnapshot`、8 ページ目の購読）。データの流れが一方通行になっているので、自分の変更も他の人の変更も、同じ道を通って画面に反映されます。

## 🐍 Python と比べると

| JavaScript | Python で言うと |
|---|---|
| `document.addEventListener("click", e => ...)` | （ブラウザ専用）「クリックされたらこの関数を呼んで」と登録する |
| `if (d.tab) ... else if (d.me) ...` | `if d.get("tab"): ... elif d.get("me"): ...` |
| `{todo: "doing", ...}[x.status] \|\| "todo"` | `{"todo": "doing", ...}.get(x["status"], "todo")` |
| `const [col, id] = d.del.split(":")` | `col, id = d["del"].split(":")` |
| `confirm("削除しますか？")` | `input("削除しますか？ (y/n) ") == "y"` |

## 🔑 キーワード

- **イベント**：クリック・送信・入力など、利用者の操作
- **イベント委任**：親の要素（ここでは document）でまとめてイベントを受け止める方法
- **バブリング**：イベントが内側の要素から外側へ伝わっていく性質
- **closest**：外側へたどって、条件に合う一番近い要素を探すメソッド
- **dataset / data 属性**：HTML 要素に付けたメモ書きを、JavaScript から読む仕組み
- **モーダル**：画面の上に重ねて出す小窓
- **FormData**：フォームの入力値をまとめて取り出す仕組み

## ⚠️ AI のコードとしてのチェックポイント

- ✅ イベント委任で、画面を作り直してもボタンの処理が消えない
- ✅ 削除の前に確認を出している
- ✅ 名前が未選択なら書き込む前に選ばせる
- ⚠️ アイデア以外の保存（`store.add` / `update` / `remove`）は **失敗しても何も表示されない**。通信が切れていると、追加したつもりのタスクが消えたように見えることがある（Firestore はオフラインでも一時的に覚えておき、つながったら送る機能があるので、多くの場合は後で反映される）
- ⚠️ 写真を拡大表示するとき `z.src` をそのまま HTML に入れている（6 ページ目と同じ注意点）
- ⚠️ 長い `if / else if` の連続。機能が増えるとさらに長くなるので、data 属性ごとの処理を対応表（オブジェクト）にまとめる書き方もある
