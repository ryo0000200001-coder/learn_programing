## 📄 解説するコード（96〜143 行目）

```javascript
const FIREBASE_CONFIG = {
  apiKey: "***",
  authDomain: "popup-2027.firebaseapp.com",
  projectId: "popup-2027",
  storageBucket: "popup-2027.firebasestorage.app",
  messagingSenderId: "***",
  appId: "***",
};

const DEFAULT_SETTINGS = { title: "POP UP 2027", date: "2027-09-01", members: ["メンバーA", "メンバーB", "メンバーC"] };
const COLS = ["tasks", "milestones", "logs", "ideas", "expenses"];

// ---------- データ層 ----------
let store;
if (FIREBASE_CONFIG) {
  const { initializeApp } = await import("https://www.gstatic.com/firebasejs/10.12.2/firebase-app.js");
  const fs = await import("https://www.gstatic.com/firebasejs/10.12.2/firebase-firestore.js");
  const db = fs.getFirestore(initializeApp(FIREBASE_CONFIG));
  const onErr = e => { console.error(e); S.error = "データベースに接続できません（" + (e.code || e.message) + "）。Firestore の作成とルールを確認してください。"; render(); };
  store = {
    live: true,
    sub(col, cb) { return fs.onSnapshot(fs.collection(db, col), s => cb(s.docs.map(d => ({ id: d.id, ...d.data() }))), onErr); },
    subSettings(cb) { return fs.onSnapshot(fs.doc(db, "meta", "settings"), s => cb(s.exists() ? s.data() : null), onErr); },
    add(col, d) { return fs.addDoc(fs.collection(db, col), { ...d, createdAt: Date.now() }); },
    update(col, id, d) { return fs.updateDoc(fs.doc(db, col, id), d); },
    remove(col, id) { return fs.deleteDoc(fs.doc(db, col, id)); },
    saveSettings(d) { return fs.setDoc(fs.doc(db, "meta", "settings"), d); },
  };
} else {
  const listeners = {};
  const read = k => { try { return JSON.parse(localStorage.getItem("pu:" + k)) } catch { return null } };
  const write = (k, v) => { try { localStorage.setItem("pu:" + k, JSON.stringify(v)) } catch {} ; (listeners[k] || []).forEach(f => f(v)); };
  window.addEventListener("storage", e => { if (e.key?.startsWith("pu:")) { const k = e.key.slice(3); (listeners[k] || []).forEach(f => f(read(k))); } });
  const on = (k, f) => { (listeners[k] ||= []).push(f); f(read(k)); };
  store = {
    live: false,
    sub(col, cb) { on(col, v => cb(v || [])); },
    subSettings(cb) { on("settings", cb); },
    add(col, d) { write(col, [...(read(col) || []), { ...d, id: crypto.randomUUID?.() || String(Math.random()), createdAt: Date.now() }]); },
    update(col, id, d) { write(col, (read(col) || []).map(x => x.id === id ? { ...x, ...d } : x)); },
    remove(col, id) { write(col, (read(col) || []).filter(x => x.id !== id)); },
    saveSettings(d) { write("settings", d); },
  };
}
```

（Firebase の設定値の一部は `***` に伏せています）

## 🧭 ひとことで言うと

**JavaScript** で書かれた、**データを保存・読み込みする窓口（`store`）** を作る部分です。Firebase（クラウド）を使う版と、localStorage（この端末だけ）を使う版の 2 種類を用意し、**どちらでも同じ名前の命令で使える** ようにしています。このシリーズで一番大事で、少しむずかしい部分です。

## 🗺️ 全体の流れ

1. `FIREBASE_CONFIG` があれば、Firebase のライブラリをネットから読み込み、データベースにつなぐ
2. 無ければ、ブラウザの localStorage を使う「お試しモード」の窓口を作る
3. どちらの場合も、`store` に同じ 7 つの命令（`sub`・`subSettings`・`add`・`update`・`remove`・`saveSettings`・`live`）をそろえる
4. 以降のコードは `store.add("tasks", {...})` のように書くだけで、保存先を気にしない

## 🔍 ブロックごとの解説

### 窓口の命令の一覧

| 命令 | 意味 | 例 |
|---|---|---|
| `sub(col, cb)` | そのデータを **見張り**、変わるたびに `cb` を呼んでもらう | タスク一覧が変わったら描き直す |
| `subSettings(cb)` | 設定（タイトル・日付・メンバー名）を見張る | |
| `add(col, d)` | 1 件追加 | タスクを追加 |
| `update(col, id, d)` | 1 件の一部を書き換え | 状態を「完了」に |
| `remove(col, id)` | 1 件削除 | |
| `saveSettings(d)` | 設定を保存 | |
| `live` | Firebase につながっているか（true / false） | 「お試しモード」の表示に使う |

`col` は **コレクション**（データの種類ごとの入れ物）の名前で、`COLS` の 5 つ（tasks・milestones・logs・ideas・expenses）のどれかです。

### Firebase 版：ライブラリを後から読み込む

```javascript
const fs = await import("https://www.gstatic.com/firebasejs/10.12.2/firebase-firestore.js");
```

`import(...)` を **関数のように** 使うと、プログラムの途中でライブラリを読み込めます（動的インポート）。結果は Promise なので `await` で待ちます。
普通は `await` は `async` 関数の中でしか使えませんが、`<script type="module">` の一番外側では例外的に使えます（トップレベル await）。

### onSnapshot：データを見張る

```javascript
sub(col, cb) { return fs.onSnapshot(fs.collection(db, col), s => cb(s.docs.map(d => ({ id: d.id, ...d.data() }))), onErr); }
```

`onSnapshot` は **「このデータが変わったら、毎回この関数を呼んで」と頼む** Firestore の機能です。自分の変更でも、他のメンバーの変更でも呼ばれます。これがリアルタイム同期の正体です。

受け取ったデータ `s.docs` は扱いにくい形なので、`map` で `{ id: "abc", title: "会場を探す", ... }` という普通のオブジェクトの配列に変換して `cb` に渡しています。`...d.data()` はスプレッド構文で、中身を展開して `id` と合体させています。

### お試し版：localStorage と「聞き手（listeners）」

```javascript
const listeners = {};
const write = (k, v) => { localStorage.setItem("pu:" + k, JSON.stringify(v)); (listeners[k] || []).forEach(f => f(v)); };
const on = (k, f) => { (listeners[k] ||= []).push(f); f(read(k)); };
```

localStorage には「変わったら知らせる」機能が無いので、**自分で作っています**。

- `listeners`：`{ tasks: [関数, ...], ideas: [...] }` のように、データの種類ごとに「知らせてほしい関数」の一覧を持つ
- `on`：関数を一覧に登録し、**すぐに一度** 今のデータで呼ぶ
- `write`：保存したあと、登録された関数を全部呼ぶ（＝変わったことを知らせる）
- `window.addEventListener("storage", ...)`：**同じブラウザの別のタブ** で変更されたときも知らせる

Firebase の `onSnapshot` と同じ動きを、小さく真似しているわけです。

### 追加・更新・削除は「配列を作り直して保存」

```javascript
update(col, id, d) { write(col, (read(col) || []).map(x => x.id === id ? { ...x, ...d } : x)); }
remove(col, id) { write(col, (read(col) || []).filter(x => x.id !== id)); }
```

- `update`：`map` で全件を見て、id が一致したものだけ `{ ...x, ...d }`（元の内容に変更を上書き）にする
- `remove`：`filter` で、id が一致しないものだけ残す＝その 1 件を消す
- `crypto.randomUUID?.()`：ランダムな ID を作る。`?.` は「この機能があれば呼ぶ」。無い古いブラウザでは `Math.random()` で代用

## 🐍 Python と比べると

| JavaScript | Python で言うと |
|---|---|
| `store = { add(col, d) {...}, ... }` | 同じメソッドを持つ 2 つのクラス `FirebaseStore` と `LocalStore` を作り、どちらかを `store` に入れる |
| `await import("...")` | `importlib.import_module(...)` で途中から読み込む |
| `list.map(x => x.id === id ? {...x, ...d} : x)` | `[{**x, **d} if x["id"] == id else x for x in lst]` |
| `list.filter(x => x.id !== id)` | `[x for x in lst if x["id"] != id]` |
| `JSON.stringify` / `JSON.parse` | `json.dumps` / `json.loads` |

**同じ使い方（インターフェース）で中身だけ取り替えられる** 設計は、fashion_news で「notion.py だけ取り替えれば LINE にも送れる」と話したのと同じ考え方です。

## 🔑 キーワード

- **データ層**：データの保存・読み込みだけを担当する部分
- **Firestore**：Firebase のデータベース。コレクション（種類）とドキュメント（1 件）でデータを持つ
- **onSnapshot**：データの変化を見張り、変わるたびに知らせてくれる Firestore の機能
- **動的インポート**：`import()` で、プログラムの途中でライブラリを読み込むこと
- **localStorage**：ブラウザにデータを保存する場所（文字列のみ。だから JSON に変換する）
- **リスナー（listener）**：「何か起きたら呼んでほしい」と登録しておく関数

## ⚠️ AI のコードとしてのチェックポイント

- ✅ 保存先の違いを `store` の中に閉じ込めていて、画面側のコードがすっきりしている
- ✅ 接続に失敗したら、画面上部に原因のヒント付きで表示する
- ✅ localStorage が使えない環境でも止まらないよう `try / catch` で守っている
- ⚠️ `apiKey` などの Firebase の設定は、**Web アプリでは公開される前提の値** で、パスワードではない（ブラウザに届く時点で誰でも見られる）。その代わり、**Firestore のセキュリティルール** で「誰が読み書きできるか」を決める必要がある。このアプリにはログインが無いので、ルールの設定がとても重要
- ⚠️ `if (FIREBASE_CONFIG)` は設定が書かれている今は常に Firebase モード。お試しモードにするには `const FIREBASE_CONFIG = null;` にする
- ⚠️ お試しモードの `update` や `remove` は、毎回全件を読み直して書き直すので、データが多いと遅くなる（お試し用なので問題ない）

## 🗣️ 30 秒で人に説明するなら

「データ層は、保存先が Firebase でも localStorage でも、同じ add・update・remove・sub の命令で使えるようにした窓口です。
Firebase 版はライブラリを動的に読み込んで、onSnapshot でデータを見張り、変わるたびに画面側に知らせます。
お試し版は localStorage には通知機能が無いので、知らせてほしい関数のリストを自分で持って、保存のたびに呼ぶことで同じ動きを再現しています。」
