## 🧭 ひとことで言うと

**Python** で書かれた、**毎朝・毎夕、日本語のファッションニュースを自動で集め、ジャンル別に整理して Notion に「朝刊」「夕刊」ページを作るロボット** です。
GitHub Actions（GitHub の自動実行サービス）が決まった時刻に起動するので、パソコンの電源が切れていても動きます。

## 🗺️ 全体の流れ

工場の流れ作業（ベルトコンベア）をイメージすると分かりやすいです。

1. **起動**：毎日 6:30 と 17:30（日本時間）に GitHub Actions がプログラムを動かす（`daily.yml`）
2. **準備**：設定ファイル（どのサイトから集めるか・ジャンルのキーワード）と、過去に載せた記事の記録を読み込む（`main.py`）
3. **集める（入力）**：8 つのニュースサイトの RSS を取ってきて、記事のリストにする（`fetch.py`）
4. **ふるいにかける**：36 時間より古い記事、ファッションと関係ない記事、重複している記事、過去に載せた記事を取り除く（`classify.py`・`dedupe.py`）
5. **仕分ける**：タイトルのキーワードで 6 つのジャンルに分け、各ジャンル新しい順に最大 20 件にする（`classify.py`・`main.py`）
6. **届ける（出力）**：Notion に「2026-11-16 朝刊」のようなページを作り、ジャンルごとに見出し＋リンクを並べる（`notion.py`）
7. **記録する**：載せた記事の URL を `seen_urls.json` に書き足し、GitHub に保存する（次回の重複防止）

## 🔍 ブロックごとの解説

### 部品ごとに 1 ファイル

このプロジェクトは、**1 つのファイルに 1 つの役割** を持たせています。

| 役割 | ファイル | たとえ |
|---|---|---|
| データの形 | `models.py` | 伝票の書式 |
| 集める | `fetch.py` | 仕入れ担当 |
| 仕分ける | `classify.py` | 仕分け担当 |
| 選別する | `dedupe.py` | 検品担当 |
| 届ける | `notion.py` | 配送担当 |
| 指示を出す | `main.py` | 工場長 |

こう分けておくと、「Notion の代わりに LINE に送りたい」となっても `notion.py` の部分だけ取り替えればよく、他は触らずに済みます。

### 設定とコードを分けている

ニュースを集めるサイトや、ジャンル分けのキーワードは **コードではなく YAML ファイル** に書いてあります。
そのため「このサイトも追加したい」「このキーワードも『スニーカー』扱いにしたい」は、Python を書き換えずに設定ファイルを直すだけでできます。

### 記録をファイルに残して、重複を防ぐ

プログラムは毎回まっさらな状態で起動するので、「昨日どの記事を載せたか」を覚えていません。
そこで `data/seen_urls.json` に **載せた記事の URL と日付** を書いておき（30 日分）、次回はそこに載っている記事を除外します。

### テストがある

`tests/test_pipeline.py` に、各部品が期待どおり動くかを確かめるテストが 11 個あります。AI に修正を頼んだときに、前の機能を壊していないかすぐに確かめられます。

## 🔑 キーワード

- **RSS**：ニュースサイトが「新着記事の一覧」を機械向けに配っている形式（XML というデータ形式）
- **Notion API**：プログラムから Notion を操作するための窓口
- **GitHub Actions**：GitHub が決まった時刻やきっかけでプログラムを動かしてくれる仕組み
- **YAML**：設定ファイルによく使われる、人が読み書きしやすいデータ形式
- **パイプライン**：集める → ふるう → 仕分ける → 届ける、のように処理を順番につなげた流れ
- **ドライラン（dry run）**：本番の書き込みをせず、結果を画面に表示するだけの試し運転

## ⚠️ AI のコードとしてのチェックポイント

- ✅ 役割ごとにファイルが分かれていて、テストもある。とても読みやすい構成
- ✅ 1 つのサイトの取得に失敗しても、他のサイトは続けて処理する
- ✅ Notion のトークン（パスワードのようなもの）は GitHub の Secrets に置いていて、コードには書いていない
- ⚠️ このリポジトリは **公開（Public）** になっている。README に Notion の親ページ ID が書かれており、`seen_urls.json` から読んだ記事の履歴も誰でも見られる。トークンが無ければページ ID だけでは操作できないが、気になるなら非公開にするとよい
- ⚠️ 要件定義書では「1 つの記事に複数のジャンルを付けてよい」となっているが、実装は **最初に当たった 1 ジャンルだけ** に入れる。仕様と実装のずれ（意図的に簡単にした可能性もある）
- 必要な準備：Notion のインテグレーション（連携用の設定）と、GitHub Secrets への `NOTION_TOKEN`・`NOTION_PARENT_PAGE_ID` の登録
