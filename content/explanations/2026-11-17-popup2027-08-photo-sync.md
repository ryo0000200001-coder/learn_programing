## 📄 解説するコード（362〜403 行目）

```javascript
// ---------- 写真 ----------
document.addEventListener("input", e => { if (e.target.matches('[data-form="ideas"] textarea')) S.ideaDraft = e.target.value; });
document.addEventListener("change", async e => {
  const inp = e.target.closest("[data-photo]"); if (!inp || !inp.files[0]) return;
  S.busy = true; render();
  try { S.ideaPhoto = await shrink(inp.files[0]); }
  catch { alert("この画像は読み込めませんでした"); }
  S.busy = false; render();
});
// 写真を縮小して JPEG の文字列にする（データベースの1件あたり上限 1MB に収める）
async function shrink(file) {
  const url = URL.createObjectURL(file);
  try {
    const img = await new Promise((ok, ng) => { const i = new Image(); i.onload = () => ok(i); i.onerror = ng; i.src = url; });
    let max = 1280, q = 0.78, out = "";
    for (let n = 0; n < 6; n++) {
      const r = Math.min(1, max / Math.max(img.naturalWidth, img.naturalHeight));
      const c = document.createElement("canvas");
      c.width = Math.round(img.naturalWidth * r); c.height = Math.round(img.naturalHeight * r);
      c.getContext("2d").drawImage(img, 0, 0, c.width, c.height);
      out = c.toDataURL("image/jpeg", q);
      if (out.length < 700000) return out;
      max *= 0.8; q -= 0.08;
    }
    return out;
  } finally { URL.revokeObjectURL(url); }
}

// ---------- 購読 ----------
let rendered = false;
const rerender = () => {
  // 入力中のフォームは消さない
  const a = document.activeElement;
  if (rendered && a && a.closest("form") && (a.value || "").length) return pending = true;
  render(); rendered = true;
};
let pending = false;
document.addEventListener("focusout", () => setTimeout(() => { if (pending && !document.activeElement?.closest("form")) { pending = false; render(); } }, 0));

store.subSettings(s => { S.settings = { ...DEFAULT_SETTINGS, ...(s || {}) }; rerender(); if (!S.me || !S.settings.members.includes(S.me)) showWho(); });
COLS.forEach(c => store.sub(c, rows => { S[c] = rows; rerender(); }));
render();
```

## 🧭 ひとことで言うと

**JavaScript** で書かれた、アプリの最後の部品です。前半は **写真をデータベースに入る大きさまで小さくする** 処理、後半は **データの変更を購読して画面を更新する**（ただし、文字を入力している最中は描き直さない）仕組みです。このシリーズで一番むずかしい部分なので、図を思い浮かべながら読みましょう。

## 🗺️ 全体の流れ

**写真を選んだとき**
1. ファイル選択の変化（`change`）を受け取る
2. 「処理中…」を表示（`S.busy = true`）
3. `shrink()` で写真を縮小し、JPEG の **文字列** にして `S.ideaPhoto` に入れる
4. 「処理中…」を消して描き直す（プレビューが出る）

**アプリの起動時（購読の開始）**
1. 設定と 5 種類のデータを購読する
2. データが変わるたびに `S` に入れて `rerender()`
3. `rerender()` は、誰かが文字を入力中なら描き直しを **保留** し、入力欄から離れたときにまとめて描き直す

## 🔍 ブロックごとの解説

### なぜ写真を小さくする？

Firestore は **1 件のデータの大きさが最大 1MB** という決まりがあります。スマホの写真は数 MB あるので、そのままでは保存できません。
このアプリは写真を別の保存場所に置かず、**写真を文字列（Data URL）に変換して、アイデアのデータの中に直接入れる** 方式なので、小さくする必要があります。

### shrink：少しずつ小さくして、入るまで試す

```javascript
let max = 1280, q = 0.78, out = "";
for (let n = 0; n < 6; n++) {
  ...
  out = c.toDataURL("image/jpeg", q);
  if (out.length < 700000) return out;
  max *= 0.8; q -= 0.08;
}
```

1. 長い辺を最大 1280 ピクセル、画質 78% で JPEG にしてみる
2. 文字列が 70 万文字より小さければ完成
3. 大きすぎたら、サイズを 80% に、画質を 8% 下げて、もう一度（最大 6 回）

| 回 | 長い辺の最大 | 画質 |
|---|---|---|
| 1 | 1280 | 0.78 |
| 2 | 1024 | 0.70 |
| 3 | 約 819 | 0.62 |
| … | … | … |

70 万文字にしているのは、1MB の上限に対して、文字（タイトルなど）の分の余裕を残すためです。

### canvas：ブラウザの中の「お絵かき帳」

```javascript
const c = document.createElement("canvas");
c.getContext("2d").drawImage(img, 0, 0, c.width, c.height);
out = c.toDataURL("image/jpeg", q);
```

画面に見えない **お絵かき帳（canvas）** を作り、写真を小さいサイズで描き写して、それを JPEG の文字列として取り出しています。画像の縮小でよく使われる方法です。

### 画像の読み込みを Promise にする

```javascript
const img = await new Promise((ok, ng) => { const i = new Image(); i.onload = () => ok(i); i.onerror = ng; i.src = url; });
```

画像の読み込みは「終わったら onload を呼ぶ」という古い形（コールバック）です。それを `new Promise` で包んで、`await` で待てる形に変えています。

- `ok`（resolve）：成功したら呼ぶ → `await` の結果が `i` になる
- `ng`（reject）：失敗したら呼ぶ → 例外になり、呼び出し元の `catch` で「読み込めませんでした」と表示

`URL.createObjectURL` で作った一時的な URL は、`finally` の `revokeObjectURL` で **必ず片付けて** います（メモリの節約）。

### rerender：入力中は描き直さない

`render()` は画面を丸ごと作り直すので、**文字を入力している最中に他のメンバーの変更が届くと、入力中の文字が消えてしまいます**。それを防ぐ工夫です。

```javascript
const a = document.activeElement;
if (rendered && a && a.closest("form") && (a.value || "").length) return pending = true;
```

「今カーソルがあるのがフォームの中で、何か入力されている」なら、描き直さずに `pending = true`（あとで描き直す印）だけ付けて終わります。

```javascript
document.addEventListener("focusout", () => setTimeout(() => {
  if (pending && !document.activeElement?.closest("form")) { pending = false; render(); }
}, 0));
```

入力欄からカーソルが離れたとき（`focusout`）に、印が付いていれば描き直します。
`setTimeout(..., 0)` は「今の処理が終わった直後に実行して」という意味で、**カーソルの移動先が確定してから** 調べるためのものです。

アイデアの下書き（`S.ideaDraft`）は、入力のたびに `S` に保存しているので、描き直しても消えません。

### 購読の開始：アプリが動き出す場所

```javascript
store.subSettings(s => { S.settings = { ...DEFAULT_SETTINGS, ...(s || {}) }; rerender(); ... });
COLS.forEach(c => store.sub(c, rows => { S[c] = rows; rerender(); }));
render();
```

- 設定を購読：届いた設定を **初期値に上書き** する形で入れる（`{ ...初期値, ...届いた値 }`）。自分の名前が今のメンバーにいなければ「あなたは誰？」を出す
- 5 種類のデータを購読：届くたびに `S.tasks` などを入れ替えて描き直す
- 最後の `render()`：データが届く前に、まず一度画面を出しておく

ここが、ここまでのページで見てきた部品が **一本の流れにつながる** 場所です。

```text
操作（7 ページ目）→ store に保存（3 ページ目）→ 変更の知らせ（ここ）→ S を更新 → render（5・6 ページ目）
```

## 🐍 Python と比べると

| JavaScript | Python で言うと |
|---|---|
| `new Promise((ok, ng) => ...)` | `asyncio.Future` を作って、終わったら `set_result` する |

| `{ ...DEFAULT_SETTINGS, ...s }` | `{**DEFAULT_SETTINGS, **s}` |
| `setTimeout(f, 0)` | `loop.call_soon(f)`（今の処理の直後に実行） |

## 🔑 キーワード

- **Data URL**：画像などを `data:image/jpeg;base64,...` という文字列で表したもの
- **canvas**：ブラウザの中で絵を描いたり画像を加工したりできる要素
- **Promise 化**：コールバック形式の処理を、`await` で待てる形に包むこと
- **購読（subscribe）**：データの変化を見張り、変わったら知らせてもらうこと
- **フォーカス**：今どの入力欄にカーソルがあるか（`document.activeElement`）
- **保留フラグ**：「あとでやる」ことを覚えておく印（ここでは `pending`）

## ⚠️ AI のコードとしてのチェックポイント

- ✅ 写真を上限に収まるまで段階的に小さくし、失敗したら分かりやすく知らせる
- ✅ 一時的な URL を `finally` で必ず片付けている
- ✅ 入力中に他の人の変更が届いても、入力が消えないよう工夫している
- ⚠️ 写真をデータベースの中に文字列で保存しているので、アイデアが増えると **アプリを開くたびに全部の写真を読み込む** ことになり、重く・通信量が多くなる。写真が増えるなら Firebase Storage（ファイル置き場）に分けるのが一般的
- ⚠️ 6 回小さくしても 70 万文字を超える場合でも、そのまま返している。その場合はデータベースへの保存に失敗し、「投稿に失敗しました」と表示される
- ⚠️ `pending` は使われる行より後ろ（398 行目）で宣言されている。実際に使われるのは起動後なので動くが、宣言を上にまとめた方が読みやすい
