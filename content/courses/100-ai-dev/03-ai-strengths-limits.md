## このレッスンのゴール

- ハルシネーション（もっともらしい作り話）とは何か説明できる
- AI の答えを確かめる方法を 3 つ挙げられる

## 得意なこと

- よくある処理を素早く書く（ファイル処理、Web API、画面の部品…）
- 書き方を別の言語に変換する
- エラーメッセージから原因の候補を挙げる
- コードの説明、命名、リファクタリング（読みやすく整理し直すこと）

## 苦手・注意が必要なこと

| 苦手なこと | なぜ起きる？ | どう備える？ |
|---|---|---|
| 存在しない関数・ライブラリ・オプションを書く | もっともらしい文章を作る仕組みのため | 実行して確かめる、公式ドキュメントを見る |
| 古い書き方・古いバージョン | 学習したデータの時点で知識が止まっている | バージョンを伝える、エラーが出たら最新の情報を確認 |
| あなたの環境の事情 | 見えていないものは分からない | 前提を伝える、エージェント型ならファイルを読ませる |
| 長いやりとりの後半で最初の条件を忘れる | 一度に扱える情報量に限りがある | 大事な条件は繰り返す、作業を分ける |
| 「できました」と言うが実は確認していない | 確認していないことも自信ありげに書ける | 「実行結果を見せて」「テストして」と頼む |

## ハルシネーションの例

```python
import pandas as pd
df = pd.read_csv("data.csv")
df.auto_clean()      # ← こんなメソッドは存在しない
```

文法は正しく、名前もそれらしいので、**読むだけでは気づきにくい** のが特徴です。
実行すれば `AttributeError: 'DataFrame' object has no attribute 'auto_clean'` のようなエラーで分かります。

## 確かめる 3 つの方法

1. **動かす**：一番確実。エラーが出れば、その全文を AI に返す
2. **聞き返す**：「この関数は本当に存在する？ 公式ドキュメントのどこに書いてある？」
3. **テストを書いてもらう**：期待する結果をコードで確かめる（レッスン 8）

## ⚠️ 特に慎重になる場面

- **削除・上書き**（ファイル、データベース）
- **お金・個人情報・パスワード** が関わる処理
- **AI が提案したパッケージのインストール**：名前がそれっぽいだけの別物（悪意のあるものを含む）の可能性がある。公式のページで名前を確認する

```quiz
? ハルシネーションとは？
+ AI がもっともらしいが事実と異なる内容を出すこと
- AI が処理に時間がかかること
- AI が同じ答えを繰り返すこと
> 存在しない関数やライブラリを自信ありげに書くのが典型例です。

? AI が書いたコードに知らないメソッドがあった。最も確実な確かめ方は？
- AI に「本当に大丈夫？」と聞くだけ
+ 実行してみる・公式ドキュメントで確認する
- 名前がそれらしいので信じる
> 実際に動かすか、一次情報で確認するのが確実です。

? AI が「requests2 をインストールして」と言った。まずすべきことは？
- すぐに pip install する
+ そのパッケージが本物か、公式の情報で名前を確認する
> 似た名前の偽パッケージによる攻撃があるため、インストール前に確認します。
```
