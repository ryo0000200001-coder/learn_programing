## このレッスンのゴール

- 秘密情報をコードに書いてはいけない理由を説明できる
- 環境変数と `.env` ファイル・`.gitignore` の関係が分かる

## 秘密情報とは

API キー、パスワード、トークン、データベースの接続文字列など、**知られると勝手に使われるもの** です。
API キーが漏れると、他人に使われて **料金を請求される** こともあります。

## なぜコードに書いてはいけない？

- GitHub に push すると、公開リポジトリなら **世界中から見える**
- 非公開でも、共有した相手や将来のメンバーに見える
- Git は履歴を残すので、**あとで消しても過去のコミットに残る**

## 環境変数：コードの外に置く

```python
import os
api_key = os.environ["WEATHER_API_KEY"]     # 無ければ KeyError
api_key = os.getenv("WEATHER_API_KEY")      # 無ければ None
```

```javascript
const apiKey = process.env.WEATHER_API_KEY;  // Node.js
```

環境変数は、OS がプログラムに渡す「名前つきの設定値」です。コードには **名前だけ** を書き、値は外から渡します。

## .env ファイル

```text
# .env（このファイルは Git に入れない）
WEATHER_API_KEY=abc123
DATABASE_URL=postgres://...
```

```text
# .gitignore
.env
```

`.env` に値を書き、`python-dotenv` や多くのフレームワークがそれを環境変数として読み込みます。
**`.gitignore` に `.env` があるか** は、AI のプロジェクトで必ず確認したいポイントです。

代わりに、値を空にした **`.env.example`** を Git に入れて「こういう設定が必要」と伝えるのが慣習です。

## もし漏らしてしまったら

1. **すぐにそのキーを無効化（削除・再発行）する**（サービスの管理画面で）
2. コードを環境変数を使う形に直す
3. 「コミットを消せば大丈夫」ではない：一度 push したら、もう漏れたものと考える

## ⚠️ ブラウザで動くコードに注意

フロントエンド（ブラウザで動く JavaScript）に書いたキーは、**利用者全員が見られます**。
`.env` に書いていても、ビルド時に埋め込まれるもの（`VITE_`、`NEXT_PUBLIC_` で始まる名前など）は公開されます。
秘密のキーを使う処理はサーバー側に置く、というのが基本です。

```quiz
? API キーを誤って GitHub に push してしまった。最初にすべきことは？
- 該当のコミットを削除する
+ そのキーを無効化して新しいキーを発行する
- リポジトリ名を変える
> 一度公開されたキーは漏れたものと考え、まず無効化します。

? `.env` ファイルについて正しいのは？
+ .gitignore に入れて、Git の管理から外す
- 必ず Git にコミットする
- コードの中に貼り付ける
> 共有したいときは値を空にした .env.example を使います。

? ブラウザで動く JavaScript に書いた API キーは？
- 利用者からは見えない
+ 利用者が見ることができる
> ブラウザに届くコードはすべて見られる前提で考えます。
```
