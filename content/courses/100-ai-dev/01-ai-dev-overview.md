## このレッスンのゴール

- AI を使った開発の 3 つの形（チャット・補完・エージェント）を説明できる
- AI に任せても **人間に残る仕事** を挙げられる

## 3 つの使い方

| 形 | どんなもの | 例 |
|---|---|---|
| 💬 **チャット型** | 質問すると答えやコードを返す。コピーして使う | Claude、ChatGPT などのチャット画面 |
| ✍️ **補完型** | エディタで書いている途中に、続きを提案する | GitHub Copilot などの入力補完 |
| 🤖 **エージェント型** | 目的を伝えると、ファイルを読み・書き・コマンドを実行し・確認まで自分で進める | Claude Code など |

このサイト自体も、エージェント型の Claude Code が作っています。
エージェント型ほど **任せられる範囲が広い** 代わりに、**何をしたかを人間が確認する力** が大事になります。

## 開発の流れはどう変わる？

| 作業 | 以前 | AI と一緒なら |
|---|---|---|
| 何を作るか決める | 人間 | **人間**（AI に相談はできる） |
| コードを書く | 人間 | 主に AI |
| 動くか確かめる | 人間 | AI も実行・テストできるが、**最終判断は人間** |
| 説明・保守する | 人間 | **人間**（AI に聞きながら） |

## 人間に残る 4 つの仕事

1. **目的を決める**：何のために、何を作るか
2. **伝える**：AI が迷わないように条件を言葉にする（次のレッスン）
3. **確かめる**：コードを読み、動かし、安全か判断する
4. **責任を持つ**：公開する・人に渡すのは自分

このサイトで「コードを読んで説明する力」を鍛えているのは、まさに 3 と 4 のためです。

## よくある誤解

- ❌「AI が書いたから正しい」→ もっともらしい間違いを書くことがある（レッスン 3）
- ❌「読めなくても動けばいい」→ 壊れたとき、AI に何を頼めばいいかも分からなくなる
- ⭕「AI は優秀な同僚。でもレビューは自分の仕事」

```quiz
? ファイルの編集やコマンドの実行まで自分で進める AI の形は？
- 補完型
+ エージェント型
- チャット型
> 目的を伝えると、読む・書く・実行・確認を繰り返して進めます。

? AI と一緒に開発するとき、人間に最後まで残る仕事は？
- コードを 1 行ずつタイプすること
+ 目的を決めることと、結果を確かめて責任を持つこと
- 文法を暗記すること
> 書く作業は AI に任せられても、判断と責任は人間に残ります。
```
