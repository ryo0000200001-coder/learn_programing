## このレッスンのゴール

- AI のコードを使う前に確認すべき点を 5 つ挙げられる
- 「動いた」と「正しい」は別物だと説明できる

## AI のコードは「よくできた下書き」

AI はとても上手にコードを書きますが、あなたの環境や目的を完全には知りません。
**最終的に責任を持つのは使う人** です。次の 5 点を習慣にしましょう。

## ✅ チェック 1：目的と合っているか

頼んだことと、コードがしていることは一致していますか？
「CSV を読み込んで合計を出す」と頼んだのに、ファイルを **書き換える** 処理が混ざっていないか確認します。

## ✅ チェック 2：前提（環境・ライブラリ）は何か

- 必要なライブラリ（`import` の行）はインストール済み？
- ファイルの場所（パス）は自分の環境に合っている？
- Python や Node.js のバージョンは？

## ✅ チェック 3：うまくいかない時にどうなるか

ファイルが無い、ネットが切れている、入力が空…。
**エラー処理**（`try` / `except` など）が無いと、そこで止まってしまいます。

## ✅ チェック 4：秘密情報と危ない操作

```python
API_KEY = "sk-1234567890abcdef"   # ← コードに直接書くのは危険
```

- パスワードや API キーがコードに直書きされていないか（環境変数を使うのが基本）
- `rm -rf`、`DELETE FROM` など **消す系** の操作が無いか
- ユーザーの入力をそのまま SQL やコマンドに混ぜていないか

## ✅ チェック 5：自分の言葉で説明できるか

最後はこれです。**人に説明できないコードは、壊れたときに直せません。**
「30 秒で説明するなら？」を自分に問いかけてみましょう。

## まとめ

| チェック | 一言で |
|---|---|
| 目的 | 頼んだ通り？ |
| 前提 | 自分の環境で動く？ |
| 失敗時 | 壊れたらどうなる？ |
| 安全 | 秘密・削除・入力は大丈夫？ |
| 説明 | 自分の言葉で言える？ |

```quiz
? API キーの扱いとして良いのは？
- コードの先頭に直接書く
+ 環境変数などコードの外に置く
- コメントに書いておく
> コードに書くと、GitHub などに公開したときに漏れてしまいます。

? 「AI のコードを実行したら動いた」。これで十分と言える？
- はい、動けば正しい
+ いいえ、目的・失敗時・安全性も確認が必要
> 動くことと、正しく安全であることは別です。
```
