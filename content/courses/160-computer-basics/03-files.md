## このレッスンのゴール

- ファイルが「バイトの並び」であることと、テキストファイル・バイナリファイルの違いを説明できる
- 拡張子が何を決めていて、何を決めていないかが分かる
- `open(..., "rb")`・改行コード `\r\n` が出てくるコードを読める

場所（パス）の書き方は、ターミナルと Git のコースのレッスン 1 でくわしく扱います。

## ファイル ＝ 名前の付いたバイトの並び

ストレージ（レッスン 1 の本棚）に入っているのは、どんなファイルも **バイト（0〜255 の数）の並び** です。
その並びを「文字として読む約束」で作ったものが **テキストファイル**、それ以外が **バイナリファイル** です。

| | テキストファイル | バイナリファイル |
|---|---|---|
| 中身 | 文字コード（レッスン 5）で文字を表したバイト | 画像・音声・圧縮データなど、文字ではないバイト |
| 例 | `.py` `.js` `.txt` `.csv` `.json` `.md` `.html` | `.png` `.jpg` `.mp3` `.zip` `.xlsx` `.exe` |
| メモ帳で開くと | 読める | 意味不明な記号だらけ |

```python
with open("memo.txt", "rb") as f:        # "rb" = バイトのまま読む（read binary）
    print(f.read())
# b'\xe8\xb2\xb7\xe3\x81\x84\xe7\x89\xa9\n\xe3\x82\x8a...'   ← 「買い物」「りんご」の UTF-8

with open("photo.png", "rb") as f:
    print(f.read(8))                      # 先頭 8 バイトだけ
# b'\x89PNG\r\n\x1a\n'                   ← PNG 画像は必ずこの 8 バイトで始まる
```

（どちらも実際に実行した結果です。`b'...'` はバイト列、`\xe8` は 16 進数で書いた 1 バイト。レッスン 2）

### 画像をテキストとして開くと

```python
open("photo.png", encoding="utf-8").read()
# UnicodeDecodeError: 'utf-8' codec can't decode byte 0x89 in position 0: invalid start byte
```

「0 番目のバイト 0x89 は UTF-8 の文字として読めません」というエラーです。画像はバイナリなので、`"rb"` で開く必要があります。

| `open` のモード | 意味 | 返ってくるもの |
|---|---|---|
| `"r"`（省略時） | テキストとして読む | `str`（文字列） |
| `"w"` | テキストとして書く（**中身を消してから**） | |
| `"a"` | テキストとして末尾に追加 | |
| `"rb"` / `"wb"` | バイトのまま読む／書く | `bytes` |

⚠️ `"w"` は、開いた瞬間に元の中身が消えます。AI のコードで、大事なファイルを `"w"` で開いていないか確認しましょう。

## 拡張子は「名札」にすぎない

`report.final.csv` の **最後の `.` から後ろ（`.csv`）が拡張子** です。

```python
from pathlib import Path
p = Path("data/2026/report.final.csv")
p.name     # 'report.final.csv'
p.stem     # 'report.final'
p.suffix   # '.csv'
p.parent   # data/2026
```

拡張子が決めているのは、**どのアプリで開くか（OS の目安）だけ** です。中身は変わりません。

- `photo.png` を `photo.txt` に名前を変えても、中身は画像のまま（テキストとして読むと上と同じエラーになることを確認しました）
- だから、アップロードされたファイルを **拡張子だけで判断するのは危険** です。`.jpg` という名前のプログラムが送られてくることもあります

⚠️ Windows は初期設定で **拡張子を隠します**。`memo.txt` が `memo` と表示され、`memo.txt.txt` のような二重の名前に気づけないことがあります。エクスプローラーの「表示」→「ファイル名拡張子」をオンにしておくのがおすすめです。

## 隠しファイル

名前が `.` で始まるファイルやフォルダ（`.git`、`.env`、`.gitignore`）は、Mac や Linux では **隠しファイル** として扱われ、普段は見えません。
開発ではこれらが重要な役割を持ちます（`.env` は秘密情報、`.git` は Git の記録）。「無いはず」のファイルが実はあることがあるので注意しましょう。

## 改行コード：Windows だけ違う

テキストの「改行」も、実はバイトです。

| OS | 改行のバイト | 書き方 |
|---|---|---|
| Mac・Linux | 1 バイト（0x0a） | `\n`（LF） |
| Windows（昔からの習慣） | 2 バイト（0x0d 0x0a） | `\r\n`（CRLF） |

```python
open("w.txt", "w", encoding="utf-8", newline="\r\n").write("a\nb\n")
open("w.txt", "rb").read()       # b'a\r\nb\r\n'   ← \n が \r\n で保存された
```

Python は普段、OS に合わせて自動で変換してくれます。困るのは次のような場面です。

- Git の差分で、**中身は変えていないのに全行が「変更あり」** になる（改行コードだけが変わった）
- Windows で作ったシェルスクリプトを Linux で動かすと `$'\r': command not found` というエラーが出る
- CSV の行の最後に、見えない `\r` が残る

このリポジトリにも、改行コードをそろえるための `.gitattributes` というファイルが入っています。

## AI のコードではこう出てくる

| 書き方 | 読み方 |
|---|---|
| `open(path, "rb")` / `"wb"` | 画像・PDF・zip などをバイトのまま扱っている |
| `Path(...).suffix.lower() == ".png"` | 拡張子で判定している（名札だけを見ている） |
| `encoding="utf-8"` | テキストの文字コードを指定（レッスン 5。付いていないと Windows で文字化けすることがある） |
| `newline=""` | CSV を書くときの定番。`csv` モジュールに改行を任せる |
| `.strip()` | 行の最後の `\n`・`\r\n`・空白を取り除く |

JavaScript（Node.js）では、`fs.readFileSync(path)` がバイト（Buffer）、`fs.readFileSync(path, "utf8")` が文字列を返します。Python の `"rb"` と `"r"` の違いと同じです。

```quiz
? `photo.png` の名前を `photo.txt` に変えたら、中身はどうなる？
- テキストファイルに変換される
+ 中身は画像のバイトのまま変わらない
- ファイルが壊れて開けなくなる
> 拡張子は名札にすぎません。中身のバイトは同じなので、テキストとして読もうとするとエラーになります。

? 画像ファイルを読むときの正しい `open` のモードは？
- `"r"`
- `"w"`
+ `"rb"`
> 画像はバイナリなので、文字として読まずにバイトのまま読みます（read binary）。

? Windows で編集しただけなのに、Git で全部の行が変更扱いになった。考えられる原因は？
+ 改行コードが LF から CRLF に変わった
- ファイルの拡張子が変わった
- Git が壊れた
> 改行も 1 つのバイトです。`\n` が `\r\n` に変わると、全行が別の内容として扱われます。
```
