## このレッスンのゴール

- プログラム・プロセス・スレッドの違いを説明できる
- `Address already in use` や「プロセスを終了する」の意味が分かる

## プログラムとプロセス

| | たとえ | 説明 |
|---|---|---|
| **プログラム** | レシピ本 | ストレージに保存されたファイル（`main.py`、`chrome.exe`） |
| **プロセス** | 実際に料理している台所 | プログラムを **実行している最中のもの**。メモリの一部をもらって動く |
| **スレッド** | 台所で働く料理人 | プロセスの中で、命令を順番に実行していく流れ。1 つのプロセスに 1 人以上いる |

同じプログラムでも、2 回起動すれば **プロセスは 2 つ** になります（ブラウザのウィンドウを 2 つ開くなど）。
OS は、それぞれのプロセスに **番号（PID）** と **専用のメモリ** を割り当てます。あるプロセスが他のプロセスのメモリを勝手に読んだり壊したりできないようになっています。

```python
import os
print(os.getpid())       # 1293 などの PID（実行するたびに変わる）
print(os.cpu_count())    # CPU のコア（同時に計算できる数）。この環境では 4
```

### プロセスを見る・止める

| やりたいこと | Windows | Mac / Linux |
|---|---|---|
| 一覧を見る | タスクマネージャー（Ctrl+Shift+Esc） | アクティビティモニタ／`ps`・`top` |
| 実行中のプログラムを止める | ターミナルで **Ctrl+C** | ターミナルで **Ctrl+C** |
| 番号を指定して止める | `taskkill /PID 1234` | `kill 1234` |

`npm run dev` や `uvicorn` で起動したサーバーが、ターミナルを占領したまま戻ってこないのは、**プロセスが動き続けている** からです。Ctrl+C で止めます。

## 「ポートがすでに使われています」

```text
OSError: [Errno 98] Address already in use
Error: listen EADDRINUSE: address already in use :::3000
```

（上は、同じポートを 2 回使おうとして実際に出したエラーです）

1 つのポート（バックエンドコースのレッスン 2 の「部屋番号」）は、**1 つのプロセスしか使えません**。
このエラーのほとんどは、**前に起動したサーバーがまだ動いている** のが原因です。

- 前のターミナルで Ctrl+C を押し忘れていないか確認する
- 見つからなければ、そのポートを使っているプロセスを探して止める（Windows：`netstat -ano | findstr :3000`、Mac/Linux：`lsof -i :3000`）
- または、別のポートで起動する（`--port 8001`）

## スレッド：1 つのプロセスの中で同時に進める

待ち時間の多い仕事（ダウンロード・API の呼び出し）は、料理人を増やすと速くなります。

```python
import time
from concurrent.futures import ThreadPoolExecutor

def wait(n):
    time.sleep(1)          # 1 秒かかる通信の代わり
    return n

for i in range(4):         # 順番に：約 4.0 秒
    wait(i)

with ThreadPoolExecutor(4) as ex:            # 4 つのスレッドで：約 1.0 秒
    print(list(ex.map(wait, range(4))))      # [0, 1, 2, 3]
```

（実際に測った時間です）

## スレッドの落とし穴：同じデータの取り合い

スレッドどうしは **同じメモリ（変数）を共有** します。これは便利な反面、危険でもあります。

```python
import threading, time

counter = 0
def add():
    global counter
    for _ in range(1000):
        v = counter          # ① 今の値を読む
        time.sleep(0)        #    （ここで他のスレッドに順番が回りやすくする）
        counter = v + 1      # ② 1 足して書き戻す

threads = [threading.Thread(target=add) for _ in range(4)]
for t in threads: t.start()
for t in threads: t.join()
print(counter)               # 4000 になるはずが… 1002（実行した結果）
```

2 つのスレッドが **同じ値を読んでから**、それぞれ 1 足して書き戻すと、2 回足したのに 1 しか増えません。これを **競合状態（レースコンディション）** と呼びます。
タイミング次第で起きたり起きなかったりするので、**テストでは見つかりにくい** のが厄介なところです。

### 直し方：ロック（鍵）を使う

```python
lock = threading.Lock()
def add():
    global counter
    for _ in range(1000):
        with lock:           # 鍵を持っている 1 人だけが中に入れる
            counter += 1
```

同じことは、Web サーバーで 2 人が同時に「残り 1 個の商品」を買うときにも起きます。データベースでは **トランザクション**（データベース設計のコース）で防ぎます。

## プロセス・スレッド・async の使い分け

| 方法 | Python | 向いている仕事 |
|---|---|---|
| **複数のプロセス** | `multiprocessing`、`ProcessPoolExecutor` | 計算が重い（画像処理・大量の計算）。CPU のコアを全部使える |
| **複数のスレッド** | `threading`、`ThreadPoolExecutor` | 待ち時間が多い（通信・ファイル） |
| **async / await** | `asyncio`（Python コースのレッスン 13） | 待ち時間が多い。1 つのスレッドで大量の通信をさばく |

Python には **GIL** という仕組みがあり、普通の Python ではスレッドを増やしても **計算そのものは同時に 1 つしか進みません**（Python 3.13 から GIL を外した版も試験的に提供されています）。
そのため「重い計算はプロセス、待ちが多い仕事はスレッドか async」と使い分けます。

JavaScript は基本的に **1 つのスレッド** で動き、待ち時間は `async` / `await`（Promise）で処理します。重い計算は Web Worker や Node.js の `worker_threads` で別のスレッドに回します。

## AI のコードではこう出てくる

| 見かけたら | チェック |
|---|---|
| `threading.Thread` / `ThreadPoolExecutor` で共有の変数やリストを書き換えている | ⚠️ ロックがあるか。結果を `return` で集める形のほうが安全 |
| `ProcessPoolExecutor` | 重い計算を CPU のコアに分けている。`if __name__ == "__main__":` が必要（Windows では特に） |
| `Address already in use` / `EADDRINUSE` | 前のサーバーが動いたまま。Ctrl+C か、プロセスを止める |
| `kill -9` / `taskkill /F` | 強制終了。保存処理が途中で止まる可能性がある |
| 「在庫を読む → 減らして書く」を 2 回に分けている | ⚠️ 同時に買われると在庫がずれる。データベースで 1 回の更新にするか、トランザクションに |

```quiz
? 同じプログラムを 2 回起動すると、プロセスはいくつになる？
- 1 つ（同じプログラムなので共有される）
+ 2 つ（それぞれ別の PID とメモリを持つ）
- 0 個（2 回目は起動できない）
> プロセスは「実行中のもの」なので、起動した回数だけできます。

? `npm run dev` で `EADDRINUSE: address already in use :::3000` と出た。まず確認することは？
- Node.js を入れ直す
+ 前に起動したサーバーが別のターミナルで動いたままになっていないか
- パソコンのメモリを増やす
> 1 つのポートは 1 つのプロセスしか使えません。前のサーバーを Ctrl+C で止めるか、別のポートで起動します。

? 4 つのスレッドで共有の変数 `counter` に 1000 回ずつ足したのに、4000 より小さくなった。原因は？
- スレッドは足し算ができない
- Python の整数に上限があるから
+ 複数のスレッドが同じ値を読んでから書き戻したため、足した分が消えた（競合状態）
> 「読む → 足す → 書く」の間に他のスレッドが割り込むと、更新が失われます。ロックで 1 人ずつにするか、共有の値を書き換えない作りにします。
```
