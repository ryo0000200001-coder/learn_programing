## このレッスンのゴール

- 依存ライブラリの脆弱性を、`pip-audit`・`npm audit` で調べる方法と、結果の読み方が分かる
- ロックファイルとバージョンの固定の役割を説明できる
- タイポスクワッティングや、AI が提案する「存在しないパッケージ」の危険に気づける

## 自分のコードは氷山の一角

`pip install fastapi` を 1 回実行すると、FastAPI が使う別のライブラリ（starlette・pydantic・anyio…）も一緒に入ります。JavaScript では `npm install` で何百ものパッケージが入ることも珍しくありません。

```text
自分のアプリ
 ├─ fastapi            ← 自分で選んだもの（直接の依存）
 │   ├─ starlette      ← fastapi が使うもの（間接の依存）
 │   └─ pydantic
 │       └─ ...
 └─ requests
     ├─ urllib3
     └─ idna
```

**アプリとして動くコードの大半は、他人が書いたもの** です。そこに穴があれば、自分のアプリにも穴があることになります。このように、材料（ライブラリ）の側から攻撃されることを **サプライチェーン攻撃** と呼びます。

## 古いバージョンには、知られた穴がある

ライブラリの脆弱性は、見つかると番号（CVE・PYSEC・GHSA など）が付けられ、データベースで公開されます。`pip-audit` は、それと自分の依存を照らし合わせてくれます。

```text
$ cat requirements.txt
requests==2.19.0

$ pip-audit -r requirements.txt --desc off
Found 37 known vulnerabilities in 3 packages
Name     Version ID              Fix Versions
-------- ------- --------------- -------------
requests 2.19.0  PYSEC-2018-28   2.20.0
requests 2.19.0  PYSEC-2023-74   2.31.0
...
urllib3  1.23    PYSEC-2023-212  1.26.18,2.0.7
...
```

（2018 年の requests 2.19.0 で、実際に実行した結果の一部です）

| 列 | 意味 |
|---|---|
| Name / Version | どのライブラリの、どのバージョンか。`urllib3` は自分で書いていないが、requests が連れてきた間接の依存 |
| ID | 脆弱性の番号。検索すると内容が分かる |
| Fix Versions | **このバージョン以上にすれば直る** |

`requests` 1 つを古いまま使っただけで、**連れてきた urllib3・idna も含めて 37 件**（同じものの重複を含む）見つかりました。

| 言語 | 調べるコマンド |
|---|---|
| Python | `pip-audit`（`pip install pip-audit`） |
| JavaScript | `npm audit`（npm に最初から入っている） |
| GitHub | **Dependabot**：リポジトリの設定で有効にすると、脆弱性のある依存を見つけて、更新の PR を自動で作ってくれる |

⚠️ `npm audit fix --force` は、大きなバージョンアップ（互換性の無い変更）までまとめて行うので、アプリが動かなくなることがあります。更新した後はテストを実行します。

## バージョンを固定する：ロックファイル

```text
requests           ← ⚠️ 入れるたびに最新になる。昨日と今日で中身が違うかも
requests>=2.31     ← 2.31 以上なら何でも
requests==2.32.4   ← ✅ このバージョンだけ
```

直接の依存だけでなく、**間接の依存まで含めて、全部のバージョンを記録したファイル** が **ロックファイル** です。

| 道具 | ロックファイル |
|---|---|
| npm | `package-lock.json` |
| pnpm / yarn | `pnpm-lock.yaml` / `yarn.lock` |
| uv / Poetry（Python） | `uv.lock` / `poetry.lock` |
| pip | `pip freeze > requirements.txt`（簡易版） |

ロックファイルをコミットしておくと、**誰がいつインストールしても同じものが入ります**。「昨日まで動いていたのに、新しいバージョンが出て壊れた」「乗っ取られた最新版が入った」を防げます。
その代わり、固定したままだと古くなっていくので、Dependabot などで **定期的に、確認しながら上げていく** のがセットです。

## 偽物のパッケージ

### タイポスクワッティング

人気のパッケージと **1 文字違いの名前** で、悪意のあるパッケージを公開する手口です。

```text
requests  ← 本物
reqeusts  ← 偽物の例（打ち間違いを狙う）
python-requests、requests-py ← それっぽい名前の偽物の例
```

インストールしただけで、パソコンの中の秘密（SSH の鍵、`.env`、ブラウザに保存されたパスワード）を送信するものが、実際に何度も見つかっています。Python・npm のパッケージは、インストールのときにプログラムを実行できるからです。

### AI が「存在しないパッケージ」を提案する

AI は、**もっともらしいけれど存在しないパッケージ名** を答えることがあります（AI と開発するコースの「ハルシネーション」）。攻撃者がその名前を先に登録しておくと、AI の提案どおりにインストールした人が被害にあいます。これは **スロップスクワッティング** と呼ばれ、AI での開発ならではの新しい危険です。

### インストールする前に確かめること

| 確認 | 方法 |
|---|---|
| 本当にあるか・公式か | PyPI（pypi.org）・npm（npmjs.com）のページを開く。公式ドキュメントからリンクされているか |
| 使われているか | ダウンロード数、GitHub のスター、最終更新日 |
| 名前は正確か | 1 文字ずつ見る。公式ドキュメントからコピーする |
| 本当に必要か | 標準ライブラリや、すでに入っているもので足りないか |

## 依存は少ないほど安全

ライブラリ 1 つを足すことは、**その作者と、その作者が使っているライブラリ全部を信用する** ということです。数行で書ける処理のために依存を増やさないのも、立派なセキュリティ対策です。
このサイトが、外部のライブラリを 3 つ（Markdown の変換・サニタイズ・コードの色付け）だけ、`site/vendor/` に、ファイルとして同梱しているのも、毎回ネットから取ってこない・増やさないための工夫です。

## AI のコードではこう出てくる

| 見かけたら | チェック |
|---|---|
| `pip install 聞いたことのない名前` / `npm install ...` | PyPI・npm のページで、本物か・使われているかを確認 |
| `requirements.txt` にバージョンの指定が無い | ⚠️ 入れるたびに変わる。固定するか、ロックファイルを使う |
| `package-lock.json` を `.gitignore` に入れている | ⚠️ ロックファイルはコミットする |
| 何年も前のバージョンが固定されたまま | ⚠️ `pip-audit` / `npm audit` で確認 |
| `npm audit fix --force` を勧めてくる | ⚠️ 大きなバージョンアップを含む。実行後にテスト |
| `<script src="https://どこかのCDN/...">` | 配布元が乗っ取られると影響を受ける。`integrity="sha384-..."`（中身が変わっていないかの確認）があると ✅ |

```quiz
? `pip-audit` の結果で `urllib3 1.23 ... Fix Versions 1.26.18` と出たが、自分は urllib3 をインストールした覚えがない。なぜ？
- pip-audit の間違い
+ 自分が入れた requests などが、urllib3 を間接の依存として連れてきたから
- Python に最初から入っているから
> ライブラリは別のライブラリを使っています。間接の依存の脆弱性も、自分のアプリの脆弱性になります。

? ロックファイル（`package-lock.json` など）をコミットする主な理由は？
- ファイルの容量を減らすため
+ 間接の依存まで含めて、誰がいつインストールしても同じバージョンが入るようにするため
- ライブラリを自動で最新にするため
> 全部のバージョンが固定されるので、意図しない更新や、乗っ取られた最新版が入るのを防げます。更新は確認しながら別に行います。

? AI が「この処理には `fastjson-parser-pro` を使うとよいです」と提案してきた。まずすることは？
- すぐに `pip install fastjson-parser-pro` を実行する
+ PyPI で本当に存在するか、公式のものか、使われているかを確認する（標準ライブラリで足りないかも考える）
- AI が言うなら確実に存在するので、気にしない
> AI は存在しないパッケージ名を答えることがあり、その名前で悪意のあるパッケージが登録されている場合があります。インストールの前に確認します。
```
