## このレッスンのゴール

- 並行作業でぶつかる（コンフリクトする）仕組みを説明できる
- ぶつかりにくい仕事の分け方が分かる
- 生成されるファイル（このサイトの `data.js` など）の注意点が分かる

## 実際に起きたこと

このサイトを作っている間に、**別の Claude の会話** が並行してコースを追加していました。

```text
会話 A（claude/ecstatic-...）：バックエンドのコースを追加
会話 B（claude/topic-courses）：セキュリティ・データベース設計などのコースを追加
                 ↓ どちらも自動で main に取り込まれる
              main：両方の変更が合体
```

このときは、
- **触ったフォルダが別々**（`105-backend/` と `130-security/` など）だった
- 両方が書き換えた `site/data.js` も、合体後に作り直したものと一致した

ので、問題は起きませんでした。でも、いつもうまくいくとは限りません。

## なぜぶつかるのか

2 つの会話は、それぞれ **自分の作業場所（コピー）** で作業しています（レッスン 2）。

| 状況 | 結果 |
|---|---|
| 別々のファイルを変えた | 自動で合体できる |
| 同じファイルの **別の場所** を変えた | たいてい自動で合体できる |
| 同じファイルの **同じ場所** を変えた | **コンフリクト**。どちらを残すか決める必要がある |

コンフリクトの直し方は、ターミナルと Git コース「コンフリクトの直し方」にあります。

## ぶつかりにくい分け方

| コツ | 例 |
|---|---|
| **触るフォルダ・ファイルで分ける** | 会話 A は言語コース、会話 B はテーマ別コース |
| **共通のファイルは 1 つの会話だけが触る** | README・CLAUDE.md・`app.js` の変更は 1 つの会話でまとめて |
| **始める前に最新を取り込む** | 会話を始めるときは main の最新から（クラウドの Claude は自動で clone する） |
| **小さく区切って早めに送る** | 何時間も溜めず、1 機能ごとに push する |
| **Issue で担当を分ける** | 「Issue #3 は会話 A、#4 は会話 B」 |

**迷ったら、1 つずつ頼む** のが一番安全です。

## 生成されるファイルに注意

このサイトの `site/data.js` は、`content/` の Markdown から `tools/build.py` が **作り出すファイル** です。2 つの会話がどちらも作り直すと、合体したときに中身が混ざって **おかしな形** になることがあります。

対策は単純です。

- 合体したあとで、**もう一度作り直す**（`python tools/build.py`）
- 作り直したものと、合体したものが同じか確かめる

実際、並行作業のあとで作り直して比べ、**完全に一致した** ことを確認しました。公開用の `pages.yml` も、公開の直前に必ず作り直す設定になっています。

同じ理由で、`package-lock.json` のような **自動で作られるファイル** は、コンフリクトしたら手で直さず、作り直すのが定石です。

## チームで開発するときも同じ

この考え方は、人間のチームでもまったく同じです。

- 1 つのブランチ・1 つの PR に、1 つの目的
- 共通の部分を変えるときは、先に一言伝える
- main はいつも動く状態に保つ

AI の会話を「チームのメンバー」だと思って、仕事を分けてあげましょう。

```quiz
? 2 つの会話が、同じファイルの同じ行をそれぞれ書き換えた。合体するとどうなる？
- 自動で新しい方が残る
+ コンフリクトになり、どちらを残すか決める必要がある
- 両方とも消える
> 同じ場所の変更は、自動ではどちらが正しいか決められません。

? 並行作業でぶつかりにくくする分け方として良いのは？
+ 触るフォルダ・ファイルで仕事を分ける
- 2 つの会話に同じ仕事を頼む
- 共通のファイルを両方で書き換える
> 触る場所が重ならなければ、自動で合体できます。

? site/data.js のような「自動で作られるファイル」が合体後おかしくなったら？
- 手で 1 行ずつ直す
+ 元のファイルから作り直す（python tools/build.py）
- 削除してそのままにする
> 生成されるファイルは、元から作り直すのが確実です。
```
