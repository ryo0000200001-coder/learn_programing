## このレッスンのゴール

- 「自分のパソコン」「GitHub」「Claude」の 3 つの役割を説明できる
- Claude が「今どこで作業しているか」を意識できる
- 「送る」「受け取る」が何を指しているか分かる

## まずは地図

```text
【Claude（会話）】
   │
   ├─ ファイルを読む・書く・コマンドを実行
   │    ↓
   │  【自分のパソコンの作業フォルダ】（例：書類/GitHub/onlineshop）
   │    │
   │    └─ ① git：push（送る）／pull（受け取る）
   │         ↓
   │       【GitHub のリポジトリ】
   │
   └─ ② gh：Issue を読む・作る、PR を作る、Actions の結果を見る
        ↓
      【GitHub の機能】（Issue・PR・Actions）
```

| 場所 | たとえ | 持っているもの |
|---|---|---|
| **自分のパソコン（ローカル）** | 自分の机 | 作業中のファイル。ここで試して、動かして、直す |
| **GitHub（リモート）** | 会社の共有キャビネット | 正式なコードの置き場所。履歴・Issue・PR・自動化 |
| **Claude** | 机の横にいる同僚 | 机のファイルを読み書きし、頼まれたらキャビネットとやりとりする |

## 「作業場所」を意識する

Claude と話すとき、Claude は **どこかのフォルダ** を作業場所にしています。

- 「Mac の `onlineshop` フォルダで作業している」→ そのフォルダのファイルを読んだり書き換えたりできる
- 別のフォルダのファイルは、基本的には触らない（触るときは許可を求める）

**新しい会話を始めるときに、作業するフォルダ（リポジトリ）を選ぶ** のはこのためです。このサイトの解説を頼むときに「learn_programing を選んで会話を始める」とお願いしているのも同じ理由です（Claude への指示書 `CLAUDE.md` がそのフォルダにあるので）。

## 2 本の線：ファイルの線と、GitHub の線

Claude と GitHub の間には、実は 2 種類のつながり方があります。

| 線 | 使う道具 | できること |
|---|---|---|
| ① ファイルの線 | **git**（`git push` / `git pull`） | 作業フォルダの変更を GitHub に **送る**、GitHub の最新を **受け取る** |
| ② GitHub の機能の線 | **gh** コマンド・GitHub の API | Issue を読む・作る、PR を作る、Actions の結果を見る |

同じ「GitHub」でも、**コードのやりとり（git）** と **GitHub というサービスの機能（gh）** は別の道具を通っています。だから「git は動くのに Issue が読めない」（gh にログインしていない）ということが起こります（レッスン 5）。

## よく出てくる言葉の対応

| Claude が言うこと | 何が起きているか |
|---|---|
| 「ファイルを作りました／直しました」 | 自分のパソコン（または作業場所）のファイルが変わった。**GitHub はまだ変わっていない** |
| 「コミットしました」 | 作業場所の Git の履歴に **セーブ** した。まだ GitHub には無い |
| 「push しました」「GitHub に送りました」 | GitHub に届いた |
| 「PR を作りました」 | GitHub 上に「この変更を本線に入れていい？」という提案ができた |
| 「マージしました」 | 提案が本線（main）に取り込まれた |

**「作った」「コミットした」「push した」は別の段階** です。「GitHub に無い！」と思ったら、どこまで進んだかを確かめましょう。

```quiz
? Claude が「ファイルを直してコミットしました」と言った。GitHub のリポジトリには反映されている？
- されている
+ まだされていない（push が必要）
> コミットは作業場所の履歴へのセーブ。GitHub に送るのは push です。

? Issue を読んだり PR を作ったりするのに使う道具は？
- git push
+ gh コマンド（GitHub の機能を使う道具）
- テキストエディタ
> コードの送受信は git、GitHub の機能は gh や API を通ります。

? 新しい会話を始めるときに、作業するフォルダを選ぶ理由は？
+ Claude はそのフォルダを作業場所にし、その中の指示書（CLAUDE.md）なども読むから
- 選ばないと Claude が日本語を話せないから
- GitHub にログインするため
> 作業場所によって、触れるファイルと読まれる指示が変わります。
```
