## このレッスンのゴール

- 「どこで止まっているか」を順番に調べる考え方が身につく
- よくあるトラブルの原因と直し方が分かる

## 基本：流れのどこで止まったかを調べる

このサイトの更新は、こう流れています。

```text
① Claude が書く → ② コミット → ③ push → ④ main に自動で取り込み
→ ⑤ 公開（Pages）／ ⑥ パソコンで pull → ⑦ ブラウザで表示
```

「変わっていない」ときは、**前から順に、どこまで届いているかを確かめる** のが鉄則です。

| 段階 | 確かめ方 |
|---|---|
| ②③ | Claude に「push まで終わった？」と聞く／GitHub のブランチを見る |
| ④ | GitHub で main のコミット履歴を見る |
| ⑤ | GitHub の **Actions** で「Deploy site」が成功しているか |
| ⑥ | `open-site.bat` を開いて、黒い画面のメッセージを見る |
| ⑦ | 強制再読み込み（キャッシュ）を試す |

## 実際に起きたトラブル

### ケース 1：GitHub には入っているのに、パソコンのサイトに出ない

- **原因**：パソコンのコピーが古いまま（pull していない）。タスクバーのアイコンが、pull をしない古いショートカットだった
- **調べ方**：`open-site.bat` を直接開いて、黒い画面のメッセージを確認 → `Already up to date.` なら pull はできている
- **直し方**：アイコンを `open-site.vbs`（pull してから開く）のものに作り直した

### ケース 2：開くたびに黒い画面が一瞬出る

- **原因**：`.bat` ファイルは、動くときに必ずコマンドの画面が出る仕組み
- **直し方**：画面を出さずに動かせる `.vbs` ファイルに替え、`wscript.exe` 経由のショートカットにした

### ケース 3：名前を変えたのに、スマホで変わらない

- **調べ方**：GitHub の Actions を見ると「Deploy site #18」が **Failure**
- **ログ**：`No artifacts named "github-pages" were found` ＝アップロードは成功していたが、公開役が見つけられなかった。GitHub 側の一時的な失敗
- **直し方**：同じ処理をやり直したら成功（#19）
- **さらに**：公開に成功したあとも古く見えるときは、ブラウザが前のページを覚えている（**キャッシュ**）ことが多い。強制再読み込み（Mac の Safari は `⌘` + `Option` + `R`）か、少し時間をおいて開き直す

### ケース 4：自動化の仕組みを入れようとしたら止められた

- **状況**：「main を自動で書き換える」設定を入れようとしたら、安全のための確認で止まった
- **理由**：人の確認なしに main が変わる仕組みは影響が大きいので、利用者の了承が必要
- **直し方**：デメリットを説明して、了承をもらってから入れた（レッスン 10）

## よくあるエラーメッセージ

| メッセージ（の一部） | 意味 | 対処 |
|---|---|---|
| `rejected ... (fetch first)` | GitHub に、手元に無い変更がある | pull してから push（レッスン 2） |
| `CONFLICT (content)` | 同じ場所を別々に変えた | コンフリクトを直す（レッスン 11） |
| `Authentication failed` / `Permission denied` | 身分証が無い・切れた・権限不足 | ログインし直す・権限を確認（レッスン 5） |
| `gh auth login` を求められる | gh にログインしていない | `gh auth login` |
| `Repository not found`（非公開） | 権限が無くて見えない | アクセス権を確認 |
| Actions の Failure | 自動処理の途中で失敗 | Actions の画面で、赤いステップのログを読む |

## AI に助けを求めるときのコツ

> 名前を変えたのにスマホで変わらない

だけでなく、

> GitHub の Actions で Deploy site #18 が Failure になっていて、ログに「No artifacts named github-pages were found」と出ています。原因と直し方を教えて

のように、**どこを見て・何が出ているか** を一緒に伝えると、一回で原因にたどり着きやすくなります。スクリーンショットも有効です（このサイトのトラブルも、スクリーンショットのおかげで早く解決しました）。

```quiz
? 「Claude に頼んだ変更がサイトに出ない」。最初に確かめるべきことは？
- ブラウザを替える
+ 流れの前の段階（push・main・公開）まで届いているかを順に確かめる
- リポジトリを作り直す
> どこで止まっているかを、前から順に調べるのが鉄則です。

? 公開は成功しているのに、ブラウザで古いページが見える。考えられる原因は？
+ ブラウザが前のページを覚えている（キャッシュ）
- GitHub が壊れている
- コードが消えた
> 強制再読み込みや、少し時間をおくことで解決します。

? Actions が Failure になった。原因を知るために見るものは？
- Issue の一覧
+ 失敗した実行の、赤くなったステップのログ
- README
> ログの最後の方に、エラーの内容が書かれています。
```
