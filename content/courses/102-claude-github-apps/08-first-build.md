## このレッスンのゴール

- 新しいアプリを作り始めるときの手順を説明できる
- 「小さく作って確かめる」1 周の中身が分かる
- 作業を区切るタイミング（コミットの単位）が分かる

## 全体の流れ

```text
① リポジトリを作る（GitHub に空の箱）
② 要件定義書と CLAUDE.md を置く
③ MVP の最初の 1 機能を頼む
④ 動かして確かめる
⑤ コミットして push
⑥ 次の機能（Issue）へ → ③ に戻る
```

この ③〜⑥ の 1 周を、**数時間〜1 日で終わる大きさ** にするのがコツです。

## ① リポジトリを作る

GitHub の右上の「＋」→「New repository」で作ります。

| 項目 | おすすめ |
|---|---|
| 名前 | 半角英小文字とハイフン（`popup-planner`） |
| Public / Private | 迷ったら Private（あとで変えられる） |
| README を付ける | 付ける（空のリポジトリだと clone しにくいことがある） |
| .gitignore | 使う言語のもの（Python・Node など）を選ぶ |

作ったら、自分のパソコンに clone するか、クラウドの Claude の会話でそのリポジトリを選びます。

## ② 最初に置くもの

| ファイル | 中身 |
|---|---|
| `REQUIREMENTS.md` | 要件定義書（レッスン 7） |
| `CLAUDE.md` | Claude へのプロジェクトの約束ごと（レッスン 9） |
| `README.md` | 起動の仕方・使い方（Claude に書いてもらい、増えるたびに更新） |

## ③ 1 機能ずつ頼む

> REQUIREMENTS.md の MVP のうち、「タスクの一覧と追加」だけを作って。
> データはまずブラウザの中に保存でいい。作る前に、ファイル構成と進め方を提案して。

- **「作る前に提案して」** と添えると、方向がずれていないか先に確認できる（AI と開発するコース「エージェントに任せるときの進め方」）
- 外部サービス（Firebase など）は、最初は使わず **後から差し替えられる形** にしてもらうと、つまずきにくい（popup2027 の「お試しモード」がまさにこの形でした）

## ④ 動かして確かめる

**「できました」と言われたら、必ず自分で動かします。**

| 種類 | 確かめ方 |
|---|---|
| Web サイト | `index.html` を開く、または開発用サーバー（`localhost:...`）を開く |
| Python のスクリプト | `python main.py`（`--dry-run` のような試し運転があれば使う） |
| API | `/docs` の画面から試す、テストを実行する |

うまく動かなければ、**何をして・何が起きて・何を期待していたか** を、エラーメッセージの全文と一緒に伝えます（はじめての「コードを読む」コース「エラーメッセージの読み方」）。

## ⑤ コミットの単位

| 良い単位 | 悪い単位 |
|---|---|
| 「タスクの一覧と追加を作った」 | 「今日やったこと全部」 |
| 「在庫切れラベルを追加（#3）」 | 「いろいろ修正」 |

1 つのコミット・1 つの PR に **1 つの目的**。あとで「このときの変更を取り消したい」となったとき、ピンポイントで戻せます（ターミナルと Git コース「取り消しとやり直し」）。

## ⑥ 次に進む前に

- README に、新しく増えた使い方・設定を足してもらう
- 気になったこと・あとでやりたいことは、その場で **Issue にしておく**（レッスン 6）
- ときどき「このコードを解説して」と頼んで、**自分が説明できるか** 確かめる（このサイトの「コード解説」に残ります）

## 大きくなってきたら

| 症状 | 対策 |
|---|---|
| 同じような不具合が何度も出る | テストを書いてもらう（AI と開発するコース「テストで確かめる」） |
| 1 つのファイルが長くなりすぎた | 役割ごとにファイルを分けてもらう（バックエンドコース「設計とスケール」） |
| 毎回同じことを頼んでいる | CLAUDE.md に書き足す（レッスン 9）、自動化する（レッスン 10） |

```quiz
? Claude に「できました」と言われた。次にすべきことは？
- すぐに次の機能を頼む
+ 自分で動かして、期待どおりか確かめる
- コードを全部消す
> 動かして確かめてからコミットするのが、1 周の基本です。

? 良いコミットの単位はどれ？
+ 1 つの目的ごと（例：在庫切れラベルを追加）
- 1 日の作業をまとめて 1 つ
- ファイル 1 文字ごと
> 目的ごとに分けると、あとで振り返ったり取り消したりしやすくなります。

? 最初から Firebase などの外部サービスにつながず、「後から差し替えられる形」で作るメリットは？
- 外部サービスが使えなくなる
+ 設定でつまずかずに、まず機能を動かして確かめられる
- 料金が高くなる
> popup2027 の「お試しモード」のように、保存先を後から切り替えられる作りが便利です。
```
