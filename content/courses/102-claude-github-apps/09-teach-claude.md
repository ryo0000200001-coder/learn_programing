## このレッスンのゴール

- CLAUDE.md が何のためにあり、いつ読まれるか説明できる
- 良い CLAUDE.md に書くことが分かる
- スキル・設定（許可のルール）など、ほかの育て方を知る

## Claude は会話をまたいで覚えていない

新しい会話を始めると、Claude は **前の会話の内容を覚えていません**。
「説明は日本語で」「解説はこのテンプレートで」「最後にビルドして」…を毎回言うのは大変です。

そこで、プロジェクトのフォルダに **CLAUDE.md** というファイルを置いておくと、Claude Code は会話の始めにそれを読んで、約束ごととして守ってくれます。

## このサイトの CLAUDE.md を読む

このリポジトリの一番上にある `CLAUDE.md` は、こんな構成です。

| 見出し | 書いてあること | なぜ必要？ |
|---|---|---|
| 冒頭 | このリポジトリが何か（静的な学習サイト。Claude が Markdown を書いて育てる） | 目的が分かると、細かい判断がぶれない |
| 利用者について | Python は初心者・目標は説明できること・日本語で | 説明の難しさを合わせるため |
| 返信の言語 | 途中経過もすべて日本語 | 一度英語で返したことがあったので追加した |
| よくある依頼と、やること | A. コードが貼られたら / A2. リポジトリを解説して / B. コース追加 / C. 質問 | 依頼の種類ごとの手順書 |
| テンプレート | 解説とレッスンの見出しの形 | 毎回同じ形で作るため |
| main への反映 | 自動で main に入る・利用者は Windows のアイコンで開く | 環境の事情を知っておくため |

**あなたがコードを貼るだけで、決まった形の解説ページがサイトに増えるのは、この CLAUDE.md のおかげ** です。

## 良い CLAUDE.md の書き方

| コツ | 例 |
|---|---|
| **理由も書く** | 「秘密情報は *** に伏せる（公開リポジトリなので）」 |
| **手順は番号付きで** | 「1. 解説を書く 2. build する 3. コミットして push する」 |
| **具体的なコマンドやファイル名を書く** | `python tools/build.py`、`content/explanations/` |
| **「やらないこと」も書く** | 「試しの作業は claude/ 以外のブランチで（main に入れないため）」 |
| **長くしすぎない** | 毎回読まれるので、本当に必要なことだけ。細かい資料は別ファイルにして場所を書く |
| **育てる** | 同じ注意を 2 回したら書き足す。古くなったら消す |

「一度英語で返されたので『すべて日本語』を足した」「パソコンの開き方が変わったので書き直した」のように、**困ったことがあるたびに少しずつ育てる** のが一番の近道です。
Claude に「今の会話で決まったことを CLAUDE.md に書き足して」と頼むこともできます。

## CLAUDE.md の置き場所

| 場所 | 効く範囲 |
|---|---|
| リポジトリの一番上 `CLAUDE.md` | そのプロジェクト（Git に入れればチーム全員・どのパソコンでも） |
| 自分のホームフォルダの設定（`~/.claude/CLAUDE.md`） | 自分のパソコンのすべてのプロジェクト（「いつも日本語で」など） |
| サブフォルダの `CLAUDE.md` | そのフォルダで作業するとき |

新しいプロジェクトでは、Claude Code の `/init` というコマンドで、今のコードを読んで CLAUDE.md のたたき台を作ってもらえます。

## そのほかの育て方

| 仕組み | 何をするもの | 例 |
|---|---|---|
| **スキル** | 特定の作業の手順書を、必要なときだけ読み込ませる | 「リリースの手順」「デザインのルール」 |
| **許可の設定** | 「このコマンドは毎回聞かなくていい」「これは禁止」を決める | テストの実行は許可、本番のデータベースの操作は禁止 |
| **フック** | 決まったタイミングで自動でコマンドを動かす | ファイルを書き換えたら自動で整形する |
| **スラッシュコマンド** | よく頼むことを `/` で呼べるようにする | `/review` で決まった観点のレビュー |

名前や細かい使い方は更新で変わることがあるので、使うときは「◯◯したいので、スキル（または設定）を作って」と Claude に頼むのが確実です。
まずは **CLAUDE.md を育てるだけで、ほとんどの「毎回言うのが面倒」は解決** します。

```quiz
? 新しい会話のたびに「説明は日本語で」と言わなくて済む方法は？
- 毎回最初に言う
+ CLAUDE.md に書いておく
- 英語で話しかける
> CLAUDE.md は会話の始めに読まれ、約束ごととして守られます。

? 良い CLAUDE.md の書き方として合っているのは？
+ 理由や具体的なコマンドも書き、困ったことがあるたびに少しずつ育てる
- 思いつくことを全部、できるだけ長く書く
- 一度書いたら絶対に変えない
> 毎回読まれるので、必要なことを具体的に。古くなったら直します。

? リポジトリの CLAUDE.md を Git に入れておくメリットは？
- Claude が速く動く
+ どのパソコン・クラウドの Claude でも、同じ約束ごとで作業してもらえる
- GitHub の料金が安くなる
> このサイトでも、クラウドの Claude が毎回この CLAUDE.md を読んでいます。
```
