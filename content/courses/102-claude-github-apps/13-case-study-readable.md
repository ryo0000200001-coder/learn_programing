## このレッスンのゴール

- 1 つのアプリが、依頼 → 作り直し → 自動化 → 運用と育っていく流れを説明できる
- このコースの各レッスンの考え方が、実際にどこで使われたか分かる

## 振り返り 1：最初の想像はずれる

最初の版（②）は「サイトに AI を入れる」作りでしたが、本当にほしかったのは「**Claude との会話がそのまま教材になる**」仕組みでした（③）。
これは失敗ではなく、**動くものを見たからこそ、本当にほしいものがはっきりした** 例です。MVP を早く作る意味はここにあります（レッスン 7）。

## 振り返り 2：「毎回言う」を「仕組み」に変えていった

| 毎回やっていたこと | 仕組みにしたもの |
|---|---|
| 「日本語で」「このテンプレートで」と言う | `CLAUDE.md` |
| 「main に反映して」と頼む | `auto-merge-claude.yml` |
| GitHub Desktop で Pull してから開く | `open-site.vbs` ＋ タスクバーのアイコン |
| スマホで見るときにファイルを送る | `pages.yml`（GitHub Pages） |

**面倒だと感じたら、それは仕組みにするチャンス** です。ただし仕組みが増えるほど、「どこで止まったか」を調べる場所も増えます（レッスン 12）。

## 振り返り 3：役割分担

```text
あなた：何がほしいか決める・使ってみて違和感を伝える・了承する
Claude：設計・コード・解説を書く・調べる・直す
GitHub：コードと履歴を保管・自動で取り込み・公開
パソコン／スマホ：見て学ぶ
```

このサイトのコードは、ほぼすべて Claude が書きました。それでも、**何を作るかを決め、使ってみて「違う」と言い、トラブルのスクリーンショットを送ったのはあなた** です。AI との開発で人間に残る仕事（AI と開発するコース「AI と一緒に開発するとは」）を、そのまま実践してきたことになります。

## 自分のアプリに当てはめてみよう

次のアプリを作るときは、このコースの順番でたどってみてください。

1. 3 つの場所と、作業する場所を決める（レッスン 1〜3）
2. GitHub にリポジトリを作り、ログインを確認する（レッスン 4・5）
3. AI と相談して要件定義書を作り、MVP を決める（レッスン 7）
4. CLAUDE.md を置き、1 機能ずつ作って確かめる（レッスン 8・9）
5. やることは Issue に、変更は PR で（レッスン 6）
6. くり返しの作業は自動化する（レッスン 10）
7. 困ったら、流れのどこで止まったかを調べる（レッスン 12）

そして、作ってもらったコードは **「◯◯ リポジトリを解説して」** と頼んで、このサイトで読んでみましょう。作る → 読む → 説明できる、が Readable の目指すサイクルです。

```quiz
? 最初の版から作り直すことになった（③）ことから学べることは？
- 最初の版は作らない方がよい
+ 動くものを早く見ると、本当にほしいものがはっきりする
- AI は役に立たない
> 想像のずれは、動くものを見て初めて分かることが多いです。

? 「毎回同じことを頼んでいる」と感じたときに考えるとよいことは？
+ CLAUDE.md や自動化など、仕組みにできないか
- 頼むのをやめる
- 毎回もっと長く説明する
> 面倒なくり返しは、仕組みにするチャンスです。

? このサイトづくりで、人間（あなた）が担った大事な役割は？
- コードを 1 行ずつ書くこと
+ 何を作るか決め、使って違和感を伝え、了承すること
- サーバーを管理すること
> AI と開発するときに人間に残る仕事を、実際にしてきました。
```
