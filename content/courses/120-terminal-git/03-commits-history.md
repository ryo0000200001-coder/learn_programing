## このレッスンのゴール

- 「作業中」「ステージ」「コミット済み」の 3 つの場所を説明できる
- `git status`・`git diff`・`git log` の出力を読める
- `.gitignore` の役割が分かり、`.env` がコミットされそうになっていたら気づける

AI と開発するコースの「Git の基本」の続きです。ここでは、実際に買い物メモのリポジトリを作って試した出力を読みます。

## 3 つの場所

```text
 作業ディレクトリ        ステージ（インデックス）       リポジトリ（履歴）
 ファイルを編集する場所  →  次のコミットに入れる候補  →  コミット済みの記録
              git add            git commit
```

| 場所 | たとえ | 確認するコマンド |
|---|---|---|
| 作業ディレクトリ | 机の上の下書き | `git diff` |
| ステージ | 「これを提出する」と箱に入れたもの | `git diff --staged` |
| リポジトリ | 提出済みの記録 | `git log` |

ステージがあるおかげで、**変更したファイルのうち、一部だけをコミットする** ことができます。

## git status：今どうなっている？

```text
$ git status --short
 M shopping.md
?? .env
?? app.py
```

| 記号 | 意味 |
|---|---|
| `??` | Git がまだ管理していない新しいファイル（untracked） |
| ` M`（左が空白） | 変更したが、まだステージに入れていない |
| `M `（右が空白） | 変更をステージに入れた |
| `A ` | 新しいファイルをステージに入れた |
| `D ` | 削除した |

`--short` を付けない `git status` は、次に何をすればよいかを英語で教えてくれます（`use "git add <file>..." to include in what will be committed` ＝「コミットに入れるなら git add して」）。

## git diff：何を変えた？

```diff
$ git diff
diff --git a/shopping.md b/shopping.md
index 2ec13e6..44b0a40 100644
--- a/shopping.md
+++ b/shopping.md
@@ -2,3 +2,4 @@

 - りんご
 - 牛乳
+- パン
```

| 部分 | 読み方 |
|---|---|
| `--- a/...` / `+++ b/...` | 変更前（a）と変更後（b） |
| `@@ -2,3 +2,4 @@` | 変更前の 2 行目から 3 行分が、変更後は 2 行目から 4 行分になった |
| 先頭が空白の行 | 変わっていない前後の行（場所の目印） |
| `+` の行 | 追加された行 |
| `-` の行 | 削除された行 |

1 行を書き換えた場合は、`-` の古い行と `+` の新しい行が並びます。AI と開発するコースの「差分を読む」で練習したのと同じ形です。

| コマンド | 見えるもの |
|---|---|
| `git diff` | 作業中で、まだステージに入れていない変更 |
| `git diff --staged` | ステージに入れた変更（次のコミットの中身） |
| `git diff main` | 今のブランチと main の違い |
| `git diff --stat` | ファイルごとの変更行数だけ |

## git log：これまでの記録

```text
$ git log --oneline
d978c53 Add app
3509968 Add bread
f60a6eb Add shopping list
```

上が新しい順です。左の `d978c53` は **コミット ID**（長い 16 進数の先頭 7 文字）で、コミットを指す名前として使えます。

```text
$ git show --stat 3509968
commit 35099684f118846508ae5c49d30a2ec29f6d8a7f
Author: Ryo <ryo@example.com>
Date:   Sat Nov 21 17:36:18 2026 +0000

    Add bread

 shopping.md | 1 +
 1 file changed, 1 insertion(+)
```

| よく使う形 | 意味 |
|---|---|
| `git log --oneline --graph` | ブランチの分かれ方も図で見る（次のレッスン） |
| `git log -p ファイル` | そのファイルの変更の中身ごと |
| `git show ID` | 1 つのコミットの中身 |
| `HEAD` | 今いるコミット。`HEAD~1` は 1 つ前 |

### git blame：この行は誰がいつ書いた？

```text
$ git blame -L 3,5 shopping.md
^f60a6eb (Ryo 2026-11-21 17:36:18 +0000 3) - りんご
d5398514 (Ryo 2026-11-21 17:36:26 +0000 4) - バナナ
077e9717 (Ryo 2026-11-21 17:36:26 +0000 5) - 牛乳（低脂肪）2 本
```

行ごとに、最後に変えたコミットが分かります。「この変な行はなぜある？」と思ったら、blame でコミットを見つけ、`git show` でそのときの変更とメッセージを読みます。GitHub の画面の「Blame」ボタンでも同じものが見られます。

## .gitignore：コミットしないものを決める

```text
$ git status --short
?? .env              ← 秘密情報のファイルが「新しいファイル」として見えている
```

`.gitignore` に名前を書くと、Git はそのファイルを **無いものとして扱います**。

```gitignore
# 秘密情報
.env
# Python の作業用の環境と、Python が自動で作るファイル
.venv/
__pycache__/
# JavaScript のライブラリ（npm install で作り直せる）
node_modules/
# .log で終わるファイル全部
*.log
```

`#` で始まる行はコメントです。⚠️ `.env  # 秘密情報` のように **同じ行の後ろにコメントを書くと、そこまで含めてファイル名だと思われる** ので、コメントは別の行に書きます。

```text
$ echo ".env" > .gitignore
$ git status --short
?? .gitignore        ← .env が一覧から消えた
```

⚠️ `.gitignore` は **これから** 追跡しないための設定です。すでにコミットしたファイルは消えません。秘密情報を一度でもコミットして push したら、AI と開発するコースの「秘密情報と環境変数」の手順で、**キーそのものを無効にして作り直す** 必要があります。

⚠️ `git add .`（全部をステージに）は便利ですが、`.gitignore` が無いと `.env` まで入ってしまいます。実行前に `git status` を見る習慣をつけましょう。

## よいコミットとは

| | よい | よくない |
|---|---|---|
| 大きさ | 1 つの目的ごと（「パンを追加」） | 1 週間分を 1 回で（「いろいろ修正」） |
| メッセージ | 何を・なぜが分かる（`Fix tax rounding for 8% items`） | `update`、`fix`、`aaa` |
| 中身 | そのコミットだけで動く | 途中の壊れた状態 |

コミットを小さく分けておくと、後で「この変更だけ取り消す」（レッスン 7）が簡単になります。

```quiz
? `git status --short` で `?? app.py` と表示された。意味は？
+ Git がまだ管理していない新しいファイル
- 変更してステージに入れたファイル
- 削除されたファイル
> `??` は untracked（未追跡）。`git add app.py` でステージに入れると `A ` になります。

? `git diff` に何も表示されないのに、`git status` では変更がある。考えられる理由は？
- Git が壊れている
+ 変更をすでに `git add` でステージに入れている（`git diff --staged` で見える）
- ファイルが保存されていない
> `git diff` はステージに入れる前の変更だけを表示します。ステージ済みの変更は `git diff --staged` で確認します。

? `.env` をうっかりコミットして GitHub に push してしまった。正しい対応は？
- `.gitignore` に `.env` を追加すれば、GitHub からも消えるので大丈夫
- 次のコミットで `.env` を削除すれば、履歴からも消える
+ 中のキーやパスワードを無効にして新しいものを作り直す（そのうえで追跡をやめる）
> 一度 push すると履歴に残り、誰かに見られた可能性があります。まずキー自体を無効にするのが最優先です。
```
