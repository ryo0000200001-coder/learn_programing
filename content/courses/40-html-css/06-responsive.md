## このレッスンのゴール

- `<meta name="viewport">` が何のためにあるか説明できる
- メディアクエリ（`@media`）を読み、どの画面幅で何が変わるか分かる
- 単位（px・%・rem・em・vw）を使い分けられる

**レスポンシブ** とは、1 つの HTML と CSS で、スマホ・タブレット・PC のどの画面幅でも見やすく表示することです。

## まず viewport の meta タグ

```html
<meta name="viewport" content="width=device-width, initial-scale=1">
```

これが無いと、スマホのブラウザは「PC 用のページだろう」と考えて、**幅 980px くらいの画面として表示し、全体を縮小** します。文字が豆粒のように小さくなります。
この 1 行で「画面の幅 ＝ スマホの本当の幅（375px など）で表示して」と伝えます。レッスン 1 の基本の形に入っていたのはこのためです。

## メディアクエリ：画面の幅で CSS を変える

```css
.resp { color: black; }

@media (min-width: 768px) {     /* 画面の幅が 768px 以上のときだけ */
  .resp { color: red; }
}
```

ブラウザの幅を変えて確かめると、**幅 800px では赤、375px では黒** になりました。

| 書き方 | 意味 |
|---|---|
| `@media (min-width: 768px)` | 768px **以上** のとき |
| `@media (max-width: 767px)` | 767px **以下** のとき |
| `@media (prefers-color-scheme: dark)` | 利用者がダークモードにしているとき |
| `@media print` | 印刷するとき |

Python で言うと、`if screen_width >= 768:` の中にだけ書いた CSS、というイメージです。

### モバイルファースト

```css
/* まずスマホ用（何も条件を付けない） */
.layout { display: block; }

/* 広い画面のときだけ、横に並べる */
@media (min-width: 768px) {
  .layout { display: grid; grid-template-columns: 240px 1fr; }
}
```

**スマホ用を先に書き、`min-width` で広い画面の分を足していく** 書き方を、モバイルファーストと呼びます。スマホの CSS が単純になるので、今はこちらが主流です。

| よく使う区切り（目安） | |
|---|---|
| 〜 639px | スマホ |
| 640px 〜 | 大きめのスマホ・小さいタブレット |
| 768px 〜 | タブレット |
| 1024px 〜 | ノート PC |
| 1280px 〜 | 大きな画面 |

（Tailwind CSS の `sm:`・`md:`・`lg:`・`xl:` がこの区切りです。レッスン 7）

## 単位の使い分け

| 単位 | 意味 | 使いどころ |
|---|---|---|
| `px` | 画面の点（ピクセル）の数 | 枠線の太さなど、変わってほしくないもの |
| `%` | 親の大きさに対する割合 | 幅（`width: 50%`） |
| `rem` | **ページの基準の文字の大きさ**（ふつう 16px）の何倍か | **文字の大きさ・余白**（おすすめ） |
| `em` | **親の文字の大きさ** の何倍か | ボタンの中の余白など、文字に合わせたいもの |
| `vw` / `vh` | 画面の幅／高さの 1% | 画面いっぱいの背景（`min-height: 100vh`） |

親の文字の大きさを 20px にして、子に `1.5em` と `1.5rem` を付けて測りました。

```text
font-size: 1.5em  → 30px（親の 20px × 1.5）
font-size: 1.5rem → 24px（基準の 16px × 1.5。親は関係ない）
```

`em` は **入れ子になるほど掛け算で大きくなる** ので、意図しない大きさになりがちです。文字の大きさには `rem` を使うのが無難です。
また、`rem` で書いておくと、利用者がブラウザの設定で文字を大きくしたときに、ページ全体が一緒に大きくなります。

## よくある崩れと直し方

| 症状 | よくある原因 | 直し方 |
|---|---|---|
| スマホで横スクロールが出る | 幅を `px` で固定した要素がある（`width: 800px`） | `max-width: 100%`、または `%` や Grid に |
| 画像がはみ出す | 画像が元の大きさで表示されている | `img { max-width: 100%; height: auto; }` |
| 長い URL が折り返されずにはみ出す | 単語の途中で改行できない | `overflow-wrap: anywhere;` |
| `width: 100%` ＋ padding ではみ出す | box-sizing（レッスン 3） | `box-sizing: border-box` |
| スマホで文字が小さすぎる | viewport の meta タグが無い | レッスンの最初の 1 行を入れる |
| ボタンが小さくて押しにくい | 押せる範囲が狭い | 高さ 44px 前後を目安に、padding を大きく |

## 確かめ方

ブラウザの開発者ツール（F12）の左上の **スマホとタブレットの形のボタン** を押すと、iPhone などの幅で表示できます。AI に作ってもらったページは、**PC の幅だけでなく、スマホの幅でも必ず見てみましょう**。

## AI のコードではこう出てくる

| 見かけたら | 読み方・チェック |
|---|---|
| `@media (max-width: 768px) { ... }` | 768px **以下**（スマホ・タブレット）向けの上書き。PC 用が先に書かれている（デスクトップファースト） |
| `@media (min-width: 768px)` | 768px 以上向け。モバイルファースト |
| `width: 1200px` | ⚠️ スマホではみ出す。`max-width: 1200px; margin: 0 auto;` なら OK（広い画面では 1200px で中央寄せ、狭い画面では画面いっぱい） |
| `font-size: 14px` が全部 px | 利用者の文字の大きさの設定が効かない。`rem` だと親切 |
| `height: 100vh` | スマホではアドレスバーの分だけはみ出すことがある。`100dvh`（動的な高さ）を使うコードも増えている |
