## このレッスンのゴール

- 開発環境・ステージング・本番環境の役割を説明できる
- 環境のあいだで「変わるもの」「変えてはいけないもの」が分かる
- 「手元では動いたのに本番で動かない」ときに、疑う場所の見当がつく

## 3 つの環境

| 環境 | 英語 | どこ | 誰が使う | データ |
|---|---|---|---|---|
| **開発環境** | development / local | 自分のパソコン | 自分 | 試し用。消えてもよい |
| **ステージング** | staging | 本番そっくりのサーバー | 開発者・確認する人 | 本番に似せた試し用 |
| **本番環境** | production | 公開しているサーバー | **利用者全員** | **本物**。消えたら大変 |

個人の小さなアプリでは、ステージングを省いて「開発 → 本番」の 2 つで進めることも多いです。プルリクエストごとに一時的な確認用の環境を自動で作ってくれるサービス（**プレビュー環境**）もあります（レッスン 5）。

## 環境のあいだで変わるもの

バックエンドコースのレッスン 15 の表を、もう少し細かく見ます。

| | 開発 | 本番 |
|---|---|---|
| URL | `http://localhost:8000` | `https://example.com` |
| 通信 | http（暗号化なし） | **https**（レッスン 3） |
| データベース | SQLite のファイル・手元の PostgreSQL | クラウドのデータベース |
| 秘密情報 | `.env` ファイル | クラウドのシークレット管理（レッスン 4） |
| エラーの表示 | 詳しく（どの行で落ちたか） | 利用者には「エラーが起きました」だけ。詳細はログへ（レッスン 8） |
| 自動再起動 | `--reload`（ファイルを保存すると再起動） | 付けない |
| OS | Windows・Mac | **Linux** がほとんど |
| 同時に使う人 | 1 人 | たくさん |

**変えてよいのは「設定」だけ、コードは同じ** にするのが基本です。「本番ならこうする」という `if` をコードのあちこちに書くと、本番でしか起きないバグの元になります。設定は環境変数で切り替えます（レッスン 4）。

## 「手元では動いたのに」よくある原因

| 原因 | 例 | 対策 |
|---|---|---|
| **OS の違い** | Windows では `Data.csv` と `data.csv` が同じだが、Linux では別（ターミナルと Git のコースのレッスン 1） | ファイル名の大文字・小文字をそろえる |
| **バージョンの違い** | 手元は Python 3.13、本番は 3.11 | バージョンを固定（`.python-version`、Docker のレッスン 6） |
| **ライブラリの入れ忘れ** | 手元では入っているが、`requirements.txt` に書いていない | `pip freeze` / ロックファイル（セキュリティのコースのレッスン 6） |
| **環境変数の設定忘れ** | `.env` は Git に入れないので、本番には無い | 本番の設定画面で登録する。起動時に足りないものがあれば止まるようにする（レッスン 4） |
| **ファイルの保存先** | アップロードした画像をサーバーのフォルダに保存したら、再起動で消えた | 多くのクラウドは再起動でファイルが消える。ファイルは保存用のサービス（S3・R2 など）に |
| **localhost を直接書いている** | フロントエンドのコードに `http://localhost:8000/api` | API の URL も設定にする |
| **文字コード** | Windows で作った CSV が本番で化ける（コンピュータの基礎コースのレッスン 5） | `encoding="utf-8"` を明示 |
| **時刻** | 手元は日本時間、本番のサーバーは UTC（世界標準時） | 保存は UTC、表示のときに日本時間に |

## 本番のデータを守る

本番環境で一番大事なのは **利用者のデータ** です。

- 開発中のコードを、**本番のデータベースにつないで試さない**
- 本番のデータを手元にコピーするときは、個人情報に注意する
- テーブルの変更（マイグレーション）は、手元とステージングで試してから
- **バックアップ** を取り、戻せることを確かめておく（レッスン 8）

Cloudflare D1 の `--local`（手元）と `--remote`（本番）の違い（バックエンドコースのレッスン 19）も、この話です。

## AI のコードではこう出てくる

| 見かけたら | チェック |
|---|---|
| `app.run(debug=True)`（Flask）／ `DEBUG = True`（Django） | ⚠️ 本番では必ずオフ。エラーの画面にコードや設定が出てしまう |
| `uvicorn main:app --reload` を本番の起動コマンドに | ⚠️ 開発用 |
| `fetch("http://localhost:8000/...")` | ⚠️ 本番では届かない。設定にする |
| `if os.environ.get("ENV") == "production":` があちこちに | ⚠️ 本番でしか通らない道ができる。設定の値で動きを変える形に |
| アップロードを `open(f"uploads/{name}", "wb")` で保存 | ⚠️ クラウドでは再起動で消えることが多い |
| `datetime.now()` で保存 | サーバーの時刻帯に依存。`datetime.now(timezone.utc)` で保存すると安全 |
