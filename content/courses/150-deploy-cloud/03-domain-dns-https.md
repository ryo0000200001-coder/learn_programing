## このレッスンのゴール

- ドメインを買ってから、サイトが表示されるまでの流れを説明できる
- DNS のレコード（A・AAAA・CNAME・TXT・MX）が何を表しているか読める
- HTTPS の証明書の役割と、「証明書のエラー」の意味が分かる

バックエンドコースのレッスン 2 で「DNS は名前から住所（IP アドレス）を引く電話帳」と学びました。ここでは、**自分のドメインを電話帳に載せる側** に回ります。

## ドメインを持つとは

`ユーザー名.github.io` のような URL でも公開できますが、自分の名前の住所（`example.com`）を使いたいときは **ドメイン** を買います（年に数百円〜数千円）。

| 用語 | 意味 | 例 |
|---|---|---|
| **ドメイン** | インターネット上の名前 | `example.com` |
| **サブドメイン** | ドメインの前に付ける名前。自由に作れる | `www.example.com`、`api.example.com` |
| **レジストラ** | ドメインを売っている会社 | Cloudflare Registrar、お名前.com、Squarespace（旧 Google Domains）など |
| **DNS サーバー** | そのドメインの「電話帳」を持っている場所 | 多くはレジストラや Cloudflare が用意 |

## DNS のレコード

電話帳の 1 行 1 行を **レコード** と呼びます。管理画面で、こんな表を作ります。

| 種類 | 名前 | 値 | 意味 |
|---|---|---|---|
| **A** | `example.com` | `203.0.113.10` | この名前の住所は、この **IPv4 アドレス** |
| **AAAA** | `example.com` | `2001:db8::10` | 同じく **IPv6 アドレス**（新しい形式の住所） |
| **CNAME** | `www` | `ユーザー名.github.io` | この名前は、**別の名前の別名**。住所はそっちで引いて |
| **TXT** | `example.com` | `google-site-verification=...` | 自由な文字。「このドメインの持ち主です」の証明やメールの設定に使う |
| **MX** | `example.com` | `mail.example.com` | このドメイン宛ての **メール** の受け取り先 |

（`203.0.113.10` や `2001:db8::` は、説明用に予約されている住所です）

試しに、この環境から `github.com` の住所を引くと、`140.82.113.3` でした（引くたびに変わることがあります）。

### A と CNAME の使い分け

| 公開先 | 設定するもの |
|---|---|
| 自分で借りたサーバー（IP アドレスが決まっている） | **A**（と AAAA） |
| GitHub Pages・Vercel・Render などのサービス | 多くは **CNAME**（サービスの名前に向ける）。サービス側が住所を変えても、自分は何もしなくてよい |

⚠️ ドメインそのもの（`example.com`、「ルートドメイン」「Apex」と呼ぶ）には、普通は CNAME を置けません。サービスの説明に従って A レコードを使うか、Cloudflare の「CNAME フラット化」のような機能を使います。

### サービスとつなぐ流れ（GitHub Pages の例）

1. DNS で `www` の CNAME を `ユーザー名.github.io` にする
2. GitHub のリポジトリの Settings → Pages → **Custom domain** に `www.example.com` を入れる
3. GitHub が DNS を確認し、HTTPS の証明書を自動で用意する
4. 「Enforce HTTPS」にチェック

サービス側（GitHub）にも「このドメインを使う」と登録する、**両側の設定が必要** なのがポイントです。

## TTL：書き換えがすぐ反映されない理由

各レコードには **TTL**（Time To Live、覚えておいてよい秒数）が付いています。

```text
www.example.com   CNAME   ユーザー名.github.io   TTL 3600（1 時間）
```

世界中の DNS サーバーやパソコンは、一度引いた答えを TTL の間 **覚えておき（キャッシュ）**、その間は聞き直しません。だから、レコードを書き換えても、**最大で TTL の時間、古い住所に行く人がいます**。

- 「DNS を変えたのに表示されない」→ まず少し待つ（数分〜数時間）
- 引っ越しの予定があるなら、前もって TTL を短く（300 秒など）しておく

## HTTPS と証明書

HTTPS（バックエンドコースのレッスン 2）は、通信を暗号化するだけでなく、**「本当に example.com のサーバーと話しているか」を確かめる** 仕組みでもあります。そのための身分証明書が **SSL/TLS 証明書** です。

| 証明書に書いてあること | 意味 |
|---|---|
| 対象のドメイン | `example.com`、`www.example.com` |
| 発行者（認証局） | 信頼できる会社や団体（Let's Encrypt など） |
| 有効期限 | この日まで有効 |

ブラウザは、**信頼できる発行者が、このドメインに対して発行した、期限内の証明書か** を確かめます。

- **Let's Encrypt**：無料で証明書を発行してくれる団体。GitHub Pages・Cloudflare・Render などは、裏で自動的に取得・更新してくれる
- 証明書には有効期限があり（Let's Encrypt は 90 日。今後さらに短くなる予定）、**自動で更新する** のが今の標準

### よく見る証明書のエラー

| ブラウザの表示 | よくある原因 |
|---|---|
| 「この接続ではプライバシーが保護されません」`NET::ERR_CERT_DATE_INVALID` | 証明書の期限切れ（自動更新が止まっていた） |
| `NET::ERR_CERT_COMMON_NAME_INVALID` | `www` 付きと無しなど、証明書のドメインと違う名前でアクセスした |
| 独自ドメインにしたら証明書のエラー | サービスがまだ証明書を発行していない（DNS の確認待ち）。少し待つ |
| 「保護されていない通信」 | http のまま。https に転送する設定をする |

⚠️ プログラムで `requests.get(url, verify=False)` や Node.js の `NODE_TLS_REJECT_UNAUTHORIZED=0` を見たら要注意です。証明書の確認を **切っている** ので、偽のサーバーにつながっても気づけません。エラーを消すために AI が提案しがちな書き方です。

## AI のコードではこう出てくる

| 見かけたら | 読み方・チェック |
|---|---|
| 「DNS に `CNAME www → xxx.pages.dev` を追加してください」 | サービスの名前への別名。サービス側でもドメインの登録が必要 |
| 「TXT レコードに `_vercel` … を追加」 | ドメインの持ち主であることの証明 |
| `verify=False` / `rejectUnauthorized: false` | ⚠️ 証明書の確認を切っている。本番では使わない |
| `http://` の URL がコードに直接書かれている | 本番は https に |
| CORS の設定に `https://example.com` と `https://www.example.com` | 別の名前として扱われる。両方使うなら両方書く |
