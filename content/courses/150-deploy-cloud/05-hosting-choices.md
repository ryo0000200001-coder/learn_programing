## このレッスンのゴール

- ホスティングの種類ごとに、自分が面倒を見る範囲と料金の仕組みを説明できる
- コールドスタートや無料枠のスリープなど、選ぶときに知っておくべき落とし穴が分かる
- 作りたいものに合わせて、候補を 2〜3 個に絞れる

バックエンドコースのレッスン 15 で、ホスティングの種類を表で見ました。ここでは **選ぶとき** に必要な知識を足します。

## 面倒を見る範囲

下に行くほど自由が増え、そのぶん自分の仕事も増えます。

| 種類 | 例 | 自分が用意するもの | サービスがやってくれること |
|---|---|---|---|
| **静的ホスティング** | GitHub Pages、Cloudflare Pages、Netlify | HTML・CSS・JS のファイル | 配信・HTTPS・世界中への配布 |
| **BaaS** | Firebase、Supabase | フロントエンドと、データのルール | データベース・ログイン・ファイル保存 |
| **サーバーレス関数** | Cloudflare Workers、Vercel Functions、AWS Lambda | 関数のコード | サーバー・台数の調整・起動と停止 |
| **PaaS** | Render、Railway、Fly.io、Heroku | アプリのコード（や Dockerfile） | サーバー・OS・HTTPS・ログ |
| **コンテナのサービス** | Google Cloud Run、AWS App Runner、Azure Container Apps | Docker のイメージ（レッスン 6） | 台数の調整・HTTPS |
| **VPS・仮想マシン** | AWS EC2、さくらの VPS、ConoHa | **全部**（OS の更新、セキュリティ、ファイアウォール…） | 機械と電源と回線 |

**上の方から考えて、できないことがあったら下に降りる** のが、手間を減らすコツです。

## 料金の仕組み

| 仕組み | どんなサービス | 気をつけること |
|---|---|---|
| **使った分だけ**（リクエスト数・計算時間） | サーバーレス、BaaS、Cloud Run | 使わなければほぼ 0 円。ただし **攻撃や無限ループで急に高額** になることがある |
| **起動している時間** | PaaS、VPS | アクセスが無くても動いている間はかかる。金額は読みやすい |
| **無料枠** | ほとんどのサービス | 上限を超えたら止まるのか、課金されるのか、確認しておく |

⚠️ 使った分だけのサービスでは、**予算のアラート（いくらを超えたら知らせる）** を必ず設定しましょう。AI のコードのバグで API を呼び続けて、一晩で高額の請求、という事故は珍しくありません。

## 知っておきたい落とし穴

### コールドスタート

サーバーレスやスリープするサービスは、しばらく使われないと **止まって** います。次のリクエストが来たときに起動するので、**最初の 1 回だけ遅い** ことがあります。これを **コールドスタート** と呼びます。

| サービス | コールドスタート |
|---|---|
| Cloudflare Workers | ほぼ気にならない（とても軽い仕組みで動くため） |
| AWS Lambda、Cloud Run | 数百ミリ秒〜数秒（言語やライブラリの大きさによる） |
| PaaS の無料プラン | 数十秒かかることも（使われないとスリープするプランがある） |

### 無料プランのスリープ・停止

PaaS の無料プランは、「15 分アクセスが無いとスリープ」「月に何時間まで」のような制限があることが多いです。個人の試作には十分ですが、**人に使ってもらうサービス** なら、制限を確かめておきます。

### ファイルが消える

PaaS・サーバーレス・コンテナのサービスは、**再起動すると、サーバーに保存したファイルが消える** ことがほとんどです（レッスン 1）。データはデータベースに、ファイルは保存用のサービス（AWS S3、Cloudflare R2 など）に置きます。

### 長い処理ができない

サーバーレスの関数には、**1 回の実行時間の上限** があります（数十秒〜数分）。動画の変換のような長い処理は、キュー（バックエンドコースのレッスン 13）と別の仕組みに分けます。

## 作りたいもの別の選び方

| 作りたいもの | まず考える候補 |
|---|---|
| このサイトのような、説明や記録のページ | **静的ホスティング**（GitHub Pages、Cloudflare Pages） |
| React などの画面＋ログイン＋データ保存（popup2027 のようなアプリ） | **静的ホスティング ＋ BaaS**（Firebase・Supabase） |
| 小さな API・Webhook の受け口・定期的な処理 | **サーバーレス**（Cloudflare Workers ＋ D1） |
| FastAPI・Django・Express の普通の Web アプリ | **PaaS**（Render、Railway、Fly.io）か **Cloud Run** |
| Next.js のアプリ | Vercel、Cloudflare（vinext など） |
| ずっと動き続ける処理（Discord のボット、WebSocket） | PaaS（スリープしないプラン）、VPS |
| 特殊なソフトを入れたい・細かく制御したい | VPS（ただし管理の手間が大きい） |

### プレビュー環境

Vercel・Netlify・Cloudflare Pages・Render などは、**プルリクエストを作るたびに、その変更だけを入れた確認用の URL** を自動で作ってくれます（**プレビュー環境**）。AI が作った PR を、マージする前に実際に触って確かめられるので、とても便利です（ターミナルと Git のコースのレッスン 6）。

## 選ぶときのチェックリスト

| 確認すること | 例 |
|---|---|
| 使う言語・フレームワークに対応しているか | Python が使えるか、WebSocket が使えるか |
| データはどこに置くか | 同じサービスのデータベースがあるか、外部につなぐか |
| 料金：無料枠の中身と、超えたらどうなるか | 止まる？課金？予算アラートはある？ |
| 地域（リージョン） | 利用者が日本なら、東京などの近い場所を選べるか |
| 出ていくとき困らないか | Docker のイメージで動くなら、他のサービスにも移しやすい |

```quiz
? 「アクセスはたまにしか無いが、0 円に近く運用したい小さな API」に向いているのは？
- VPS
+ サーバーレス関数（Cloudflare Workers など）
- 常に動いている PaaS の有料プラン
> サーバーレスは使った分だけの料金なので、アクセスが少なければほとんどかかりません。

? PaaS の無料プランに置いた API が、朝いちばんのアクセスだけ 30 秒くらいかかる。考えられる理由は？
+ 使われない間スリープしていて、最初のリクエストで起動しているから（コールドスタート）
- データベースが壊れているから
- DNS の TTL のせい
> 無料プランにはスリープするものが多く、起動に時間がかかります。気になるならスリープしないプランや別のサービスを検討します。

? 使った分だけ課金されるサービスを使うとき、最初にしておくべきことは？
- 無料枠を超えないように、アプリを公開しない
+ 予算のアラートや上限を設定しておく
- 一番大きなプランにしておく
> バグや攻撃でリクエストが急に増えると、思わぬ請求になることがあります。早めに気づけるように設定します。
```
