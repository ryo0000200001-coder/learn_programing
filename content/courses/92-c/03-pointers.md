## このレッスンのゴール

- `&x`（番地を取る）と `*p`（番地の中身）の意味を説明できる
- 関数に「値を渡す」と「番地を渡す」の違いを、実験の結果で説明できる
- NULL ポインタとセグメンテーション違反の関係が分かる

## メモリには番地がある

コンピュータの基礎コースのレッスン 1 で、メモリは「作業机」だと学びました。この机には、1 バイトごとに **番地**（アドレス）が付いています。変数は、どこかの番地に置かれた値です。

```text
番地         中身
0x7ffd...a0  120     ← price（int なので 4 バイト使う）
0x7ffd...a8  0x7ffd...a0   ← p（price の番地を入れたポインタ）
```

**ポインタ** は、「**番地を入れておく変数**」です。

## & と *

```c
int price = 120;
int *p = &price;
printf("price=%d  &price=%p  p=%p  *p=%d\n", price, (void *)&price, (void *)p, *p);
*p = 200;
printf("*p = 200 の後: price=%d\n", price);
```

```text
price=120  &price=0x7ffd...  p=0x7ffd...  *p=120
*p = 200 の後: price=200
```

（番地は実行するたびに変わります）

| 書き方 | 意味 |
|---|---|
| `int *p` | p は「int が置いてある番地」を入れる変数（int へのポインタ） |
| `&price` | price の **番地** |
| `p = &price` | p に price の番地を入れる（p は price を **指す**） |
| `*p` | p が指している番地の **中身**（= price） |
| `*p = 200` | p が指している番地の中身を 200 にする（= price が 200 になる） |

`&` は「番地をください」、`*` は「その番地の中身」と読みます。`*p = 200` で、**price という名前を一度も書かずに、price の値が変わった** のがポイントです。

⚠️ `*` は 2 つの意味で使われるので、混乱しやすいところです。

| 場所 | 意味 |
|---|---|
| 宣言（`int *p`） | 「p はポインタ」 |
| 式の中（`*p = 200`、`x = *p`） | 「p が指す中身」 |

## 関数に渡すと何が起きるか

```c
void add_tax_bad(int price) { price = price * 110 / 100; }
void add_tax(int *price) { *price = *price * 110 / 100; }

int price = 120;
add_tax_bad(price);
printf("値を渡す: %d\n", price);     // 120   ← 変わっていない
add_tax(&price);
printf("場所を渡す: %d\n", price);   // 132   ← 変わった
```

| 呼び方 | 関数が受け取るもの | 元の price は |
|---|---|---|
| `add_tax_bad(price)` | price の値の **コピー**（120） | 変わらない |
| `add_tax(&price)` | price の **番地** | 番地の中身を書き換えるので、変わる |

C の関数の引数は、**いつもコピー** です（値渡し）。元の変数を変えてほしいときは、番地をコピーして渡し、関数の中で `*` を使って書き換えます。

この話は、もう出てきています。

| 言語 | 同じ話 |
|---|---|
| Go | `func (p Product)` はコピー、`func (p *Product)` は本体（Go コースのレッスン 3）。`*` と `&` は C から来ている |
| Rust | `&x` で借りる、`&mut x` で書き換えのために借りる（Rust コースのレッスン 2）。ポインタに安全のルールを付けたもの |
| Java | オブジェクトの変数は、実は番地（参照）を持っている。`==` は番地を比べる（Java コースのレッスン 2） |
| Python | すべての変数が、実はオブジェクトへの参照。だからリストを関数に渡すと、中で変えた結果が外に見える |

### 2 つの値を入れ替える

```c
void swap(int *a, int *b) { int t = *a; *a = *b; *b = t; }

int x = 1, y = 2;
swap(&x, &y);
printf("swap: x=%d y=%d\n", x, y);   // swap: x=2 y=1
```

Python なら `x, y = y, x` で済みますが、C の関数で 2 つの変数を書き換えるには、両方の番地を渡します。C の関数は値を 1 つしか返せないので、**「結果を入れる場所の番地」を渡して、そこに書いてもらう** 書き方がよく使われます（`scanf("%d", &n)` など）。

## 構造体とポインタ：->

```c
typedef struct { char *name; int price; } Product;

Product *p = ...;
p->price = 120;       // (*p).price = 120 と同じ
```

構造体のポインタから中身を使うときは、**`->`** と書きます。PHP のメソッドの `->`（PHP コースのレッスン 3）は、ここから来ています。レッスン 5 でたくさん出てきます。

## NULL：どこも指していない

```c
int *nothing = NULL;
printf("NULL を読むと...\n");
printf("%d\n", *nothing);
```

```text
NULL を読むと...
（ここで落ちる。終了コード 139 ＝ Segmentation fault）
```

`NULL` は「**どこも指していない**」ことを表す特別な値（番地 0）です。その中身を読もうとすると、OS が **「そこはあなたのプログラムが使ってよい場所ではない」** と止めます。これが **セグメンテーション違反**（Segmentation fault、segfault）です。レッスン 1 で書式を間違えたプログラムが落ちたのも同じ理由でした。

| 言語 | 「何も指していない」を使ったら |
|---|---|
| C | セグメンテーション違反で落ちる（落ちないで、でたらめな場所を読むこともある） |
| Java | NullPointerException（どの変数かまで教えてくれる） |
| Go | panic: nil pointer dereference |
| Python | `AttributeError: 'NoneType' object has no attribute ...` |
| Rust | **そもそも null が無い**（Option で表す。Rust コースのレッスン 3） |

C の NULL を発明した人自身が、のちに「10 億ドルの間違いだった」と言ったほど、多くのバグの原因になってきました。Rust が null を無くしたのは、この反省からです。

## AI のコードではこう出てくる

| 見かけたら | 読み方・チェック |
|---|---|
| `void f(int *out)` | 結果を out の番地に書いてもらう関数 |
| `const char *s` | 中身を変えない文字列へのポインタ（読むだけ。Rust の `&str` に近い） |
| `p->name` | 構造体のポインタから中身 |
| `if (p == NULL) return -1;` | ✅ NULL チェック |
| `*p` の前に NULL かどうか確かめていない | ⚠️ 落ちる可能性 |
| `int **pp` | ポインタのポインタ（「番地の番地」）。関数の中でポインタ自体を書き換えたいとき |

```quiz
? `int x = 5; int *p = &x; *p = 10;` の後、x の値は？
- 5
+ 10
- x の番地
> p は x の番地を持っていて、`*p = 10` はその番地の中身（= x）を 10 にします。

? `void f(int n) { n = 0; }` を `f(x)` で呼んでも x が変わらない理由は？
+ C の引数はコピーなので、関数の中で変わるのはコピーだけだから
- n が int だから
- f が何も返さないから
> 元の変数を変えるには、`void f(int *n) { *n = 0; }` として `f(&x)` と番地を渡します。

? NULL ポインタの中身（`*p`）を読むと、たいていどうなる？
- 0 が返る
+ セグメンテーション違反でプログラムが落ちる
- コンパイルエラーになる
> NULL はどこも指していない値です。中身を読もうとすると OS に止められます（Java なら NullPointerException に当たる）。
```
