## このレッスンのゴール

- 知らないバックエンドのリポジトリを、決まった順番で読み始められる
- 読みながら、品質と安全のチェックができる
- AI に何を聞けば理解が深まるか分かる

## 読む順番（8 ステップ）

はじめての「コードを読む」コースの「5 つのコツ」を、バックエンド用に具体的にしたものです。

### ① 全体の地図を見る

- フォルダ構成（レッスン 16 の層：routers・services・repositories・models・schemas）
- README（起動方法・必要な環境変数）
- 依存ライブラリ（`requirements.txt` / `pyproject.toml` / `package.json`）→ FastAPI か Express か、どの ORM か

### ② 入口を探す

- Python：`app = FastAPI()` と `uvicorn` の起動コマンド
- Node.js：`app.listen(...)`、`package.json` の `scripts`
- Docker：`Dockerfile` の `CMD`（レッスン 15）

### ③ API の一覧を作る

ルーティングのデコレータ（`@app.get` / `@router.post` / `app.get(...)`）を全部探して、表にします（レッスン 5）。

| メソッド | パス | ログイン必要？ | 何をする |
|---|---|---|---|
| GET | /tasks | ✅ | 自分のタスク一覧 |
| POST | /tasks | ✅ | タスク作成 |
| ... | | | |

FastAPI なら、起動して `/docs` を開くと、この表がほぼ自動で見られます。

### ④ データの形を見る

- テーブルの定義（ORM のモデル・マイグレーション）→ どんなデータを持つアプリか
- 入出力の型紙（Pydantic・zod）→ 何を受け付けて、何を返すか

**データの形が分かると、アプリの半分は分かった** と言えます。

### ⑤ 1 つの API を、入口から出口までたどる

一番大事な API（たとえば「タスクを作る」）を 1 つ選び、

```text
ルーター → 検証 → 認証・認可 → サービス（業務のルール）→ リポジトリ（データベース）→ レスポンス
```

の順に、関数を 1 つずつ追いかけます。バックエンドの仕事の 6 ステップ（レッスン 1）がどこに書かれているかを探すイメージです。

### ⑥ 設定と秘密を見る

- 環境変数の一覧（`.env.example`・`settings.py`・`config.ts`）
- 秘密がコードに直書きされていないか（レッスン 11 の ④）

### ⑦ テストを読む

テストは「この API はこう動くはず」という **動く仕様書** です（レッスン 12）。テストの名前だけでも、意図がかなり分かります。テストが無ければ、それ自体がチェックポイントです。

### ⑧ チェックリストで点検する

レッスン 11 の 10 項目に加えて：

| 観点 | 見るところ |
|---|---|
| エラー | 想定内のエラーが正しいステータスで返るか。`except: pass` が無いか（レッスン 10） |
| 速さ | ループの中で関連データをたどっていないか（N+1）、よく検索する列にインデックスがあるか（レッスン 14） |
| 非同期 | `async def` の中で `requests` や `time.sleep` を使っていないか（レッスン 13） |
| 規模 | 今の規模に対して、構成が大げさすぎないか（レッスン 16） |

## AI への聞き方の例

読んでいて分からないところは、遠慮なく AI に聞きましょう。聞き方で、返ってくる答えの質が変わります（AI と開発するコース「伝わる頼み方」）。

> `POST /tasks` が呼ばれてから、データベースに保存されるまでに通る関数を、ファイル名つきで順番に並べて

> この API で、ログインしていない人・他人のデータを触ろうとした人は、どこで止められる？

> このプロジェクトで、本番環境に必要な環境変数を全部挙げて、それぞれ何に使われるか説明して

> このコードを、N+1 問題・SQL インジェクション・認可漏れの観点でレビューして

## 自分の言葉で説明してみる

最後に、このサイトの目的に戻りましょう。読んだバックエンドについて、次の 5 つを 30 秒で話せれば合格です。

1. **何をする** API か（誰が、何のために使う？）
2. **どんなデータ** を持っているか（主なテーブル）
3. **どうやって守っている** か（認証・認可の方法）
4. **どこで動いている** か（ホスティング・定時処理）
5. **気になる点** はどこか（チェックリストで見つけたこと）

**読みたいバックエンドのリポジトリがあれば、「◯◯ リポジトリを解説して」と頼んでください。** このコースの観点で、ファイルごとの解説シリーズを作ります。

```quiz
? 知らないバックエンドを読むとき、API の一覧を作るために最初に探すとよいのは？
+ @app.get や @router.post などのルーティングのデコレータ
- CSS ファイル
- テストの中の assert
> ルーティングを全部集めると、その API で何ができるかの一覧になります。

? 「データの形が分かると半分分かる」で見るべきものは？
- ログの出力
+ ORM のモデルやマイグレーション、Pydantic の型紙
- Dockerfile
> どんなデータを持ち、何を受け付けて返すかが、アプリの骨格です。

? 次のうち、読みながら必ず確認したい「認可」のポイントは？
- 関数名が英語かどうか
+ データを取得・更新・削除するときに、その人のデータかを確かめているか
- コメントの量
> 認可漏れは AI のコードで抜けやすく、被害が大きいポイントです。
```
