## このレッスンのゴール

- フロントエンド・バックエンド・データベースの役割の違いを説明できる
- 「なぜバックエンドが必要なのか」を 3 つ挙げられる
- 自分が作ってもらったアプリ（popup2027・fashion_news）のどこがバックエンドか言える

## レストランでたとえると

| Web の世界 | レストラン | していること |
|---|---|---|
| **フロントエンド** | ホール（客席・メニュー・店員） | 画面を見せる、操作を受け付ける。ブラウザやスマホで動く |
| **バックエンド** | 厨房 | 注文を受けて、材料を確かめ、料理を作って返す。サーバーで動く |
| **データベース** | 冷蔵庫・倉庫 | 材料（データ）をしまっておく |

お客さん（利用者）は厨房に入れません。注文は必ずホールを通し、厨房は「この注文は受けていいか」「材料はあるか」を確かめてから料理を出します。
この **「お客さんが直接さわれない場所で、確かめて・処理して・保存する」** のがバックエンドの仕事です。

## なぜバックエンドが必要？

ブラウザで動く JavaScript だけでもアプリは作れます。それでもバックエンドを置く理由は 3 つです。

1. **データを共有するため**：ブラウザの中（localStorage）に保存したデータは、その端末でしか見られない。みんなで同じデータを見るには、共通の置き場所が要る
2. **秘密を守るため**：ブラウザに届くコードは利用者に全部見える。API キーやパスワードの確認など、見られてはいけない処理はサーバー側に置く
3. **ルールを守らせるため**：ブラウザ側のチェックは、利用者が改造すれば簡単に飛ばせる。「在庫が無いのに注文できる」「他人のデータを消せる」を防ぐ最後の砦はサーバー側

## バックエンドがやっている仕事

```text
① リクエストを受け取る     「タスクを 1 件追加して」
② 誰からか確かめる（認証）  「この人はログイン済み？」
③ してよいか確かめる（認可）「この人はこのチームのメンバー？」
④ 中身を確かめる（検証）    「タイトルは空じゃない？ 日付の形は正しい？」
⑤ 処理する                  データベースに保存する、計算する、メールを送る…
⑥ レスポンスを返す         「追加しました（id: 42）」
```

このコースでは、この 6 つを 1 つずつ深く学んでいきます。

## これまで解説したアプリでは？

| アプリ | バックエンドはどこ？ |
|---|---|
| **popup2027** | 自分でサーバーを作らず、**Firebase** という「既製品のバックエンド」を使っている（BaaS：Backend as a Service）。そのため ②③ の役割を Firebase のセキュリティルールが担っている |
| **fashion_news** | 画面が無く、**GitHub Actions 上で定時に動く Python** そのものがバックエンド。リクエストを待つのではなく、決まった時刻に自分から動く「バッチ処理」型 |

バックエンドは「Web サーバー」だけではなく、**利用者から見えない所で動く処理の全般** を指すことが多いです。

## バックエンドで使われる言語

| 言語 | よく使われるフレームワーク | 特徴 |
|---|---|---|
| Python | FastAPI、Django、Flask | 書きやすい。AI・データ処理と相性が良い |
| JavaScript / TypeScript | Express、NestJS、Next.js | フロントエンドと同じ言語で書ける |
| Go | 標準ライブラリ、Gin | 速くてシンプル |
| Java / Kotlin | Spring | 大企業・銀行のシステム |
| PHP | Laravel、WordPress | 昔から Web サーバーの定番 |
| Ruby | Ruby on Rails | 素早く作れる |

言語が違っても、**「リクエストを受けて、確かめて、処理して、返す」という流れは同じ** です。このコースでは主に Python（FastAPI）で例を示し、ときどき JavaScript（Express）と見比べます。

```quiz
? API キーを使う処理をバックエンドに置く一番の理由は？
- 処理が速くなるから
+ ブラウザに届くコードは利用者に見えてしまうから
- JavaScript では API キーが使えないから
> ブラウザで動くコードは誰でも読めるので、秘密はサーバー側に置きます。

? ブラウザ側で「タイトルが空なら送信しない」チェックがある。サーバー側でも同じチェックは必要？
+ 必要。ブラウザ側のチェックは改造すれば飛ばせるから
- 不要。ブラウザでチェック済みだから
> サーバーは「最後の砦」。どんなリクエストが来ても正しく断れるようにします。

? popup2027 で、バックエンドの役割を主に担っているのは？
- GitHub Pages
+ Firebase（とそのセキュリティルール）
- index.html の CSS
> 自前のサーバーの代わりに、既製品のバックエンド（BaaS）を使っています。
```
