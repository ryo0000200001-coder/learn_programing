## このレッスンのゴール

- HTTP のリクエストとレスポンスの中身を読める
- GET・POST・PUT・PATCH・DELETE の使い分けを説明できる
- ステータスコードを見て、何が起きたか分かる

## HTTP は「手紙のやりとり」

ブラウザ（クライアント）がサーバーに **リクエスト** という手紙を送り、サーバーが **レスポンス** という返事を送ります。中身はただの文字です。

**リクエスト**

```http
POST /tasks HTTP/1.1
Host: api.example.com
Content-Type: application/json
Authorization: Bearer eyJhbGciOi...

{"title": "会場を探す", "due": "2027-01-10"}
```

**レスポンス**

```http
HTTP/1.1 201 Created
Content-Type: application/json

{"id": 42, "title": "会場を探す", "due": "2027-01-10", "status": "todo"}
```

| 部分 | リクエスト | レスポンス |
|---|---|---|
| 1 行目 | **メソッド** と パス（何をしたいか） | **ステータスコード**（結果） |
| ヘッダー | 付属情報（送る形式・名札など） | 付属情報（返す形式・キャッシュの指示など） |
| 空行のあと＝ボディ | 送るデータ（JSON など） | 返すデータ |

## メソッド：何をしたいか

| メソッド | 意味 | 例 | ボディ |
|---|---|---|---|
| **GET** | 取得する | タスク一覧を見る | なし |
| **POST** | 新しく作る | タスクを追加する | あり |
| **PUT** | 丸ごと置き換える | タスクの全項目を更新 | あり |
| **PATCH** | 一部だけ変える | タスクの状態だけ「完了」に | あり |
| **DELETE** | 削除する | タスクを消す | 普通はなし |

大事な性質が 2 つあります。

- **GET はデータを変えてはいけない**：ブラウザや検索エンジンは GET のリンクを自由にたどるので、`GET /tasks/42/delete` のような作りにすると、勝手に消されることがある
- **同じことを何回しても結果が同じ（べき等）**：GET・PUT・DELETE はべき等。POST は 2 回送ると 2 件できてしまう。ボタンの二度押し対策が必要なのは主に POST

## ステータスコード：結果の番号

最初の数字で大まかな意味が分かります。

| 番台 | 意味 | よく見るもの |
|---|---|---|
| **2xx 成功** | うまくいった | `200 OK`、`201 Created`（作成した）、`204 No Content`（成功・返すものなし） |
| **3xx 転送** | 別の場所へ | `301`（引っ越した）、`302`（一時的に別の場所）、`304`（前と同じなのでキャッシュを使って） |
| **4xx 利用者側の問題** | リクエストがおかしい | `400`（形が変）、`401`（ログインしていない）、`403`（権限がない）、`404`（無い）、`409`（衝突）、`422`（中身の検証で不合格）、`429`（多すぎ） |
| **5xx サーバー側の問題** | サーバーが失敗した | `500`（中でエラー）、`502` / `503`（裏のサーバーが応答しない・混雑） |

**401 と 403 の違い** はよく聞かれます。
- `401 Unauthorized`：**あなたが誰か分からない**（ログインしていない・トークンが無効）
- `403 Forbidden`：**誰かは分かったが、それをする権限がない**

**4xx は「リクエストを直さないと何度やっても同じ」、5xx は「時間をおけば直るかもしれない」**。fashion_news の notion.py が 429 と 5xx だけをやり直していたのは、この違いを使っています。

## ヘッダー：付属情報

| ヘッダー | 意味 |
|---|---|
| `Content-Type: application/json` | ボディは JSON です |
| `Authorization: Bearer xxx` | 私はこのトークンの持ち主です（認証） |
| `Cookie` / `Set-Cookie` | ブラウザに覚えておいてもらう小さなデータ（ログイン状態など） |
| `User-Agent` | 私はこういうプログラムです（fashion_news が名乗っていたもの） |
| `Cache-Control` | このレスポンスをどれくらい使い回してよいか |
| `Retry-After` | 何秒後にやり直せばよいか（429・503 と一緒に返る） |

## HTTP は「覚えていない」

HTTP は、**前のリクエストのことを覚えていません**（ステートレス）。1 通 1 通が独立した手紙です。
だから「ログインしている」ことを伝えるには、**毎回のリクエストに Cookie やトークンを付けて名乗る** 必要があります（レッスン 9）。

## 実際に見てみる

ブラウザで F12 →「ネットワーク」タブを開いてページを読み込むと、リクエストとレスポンスが 1 つずつ見られます。メソッド・ステータス・ヘッダーが、このレッスンの表のとおりに並んでいます。

```quiz
? タスクの状態だけを「完了」に変えるのに最も合うメソッドは？
- GET
- POST
+ PATCH
> 一部だけ変えるのは PATCH、丸ごと置き換えるのは PUT です。

? ログインせずに管理画面の API を呼んだときに返るべきステータスは？
+ 401
- 403
- 500
> 誰か分からないなら 401、誰か分かったうえで権限が無いなら 403 です。

? 500 が返ってきた。まず疑うのは？
- 送ったデータの形が間違っている
+ サーバー側のプログラムでエラーが起きている
- URL が存在しない
> 5xx はサーバー側の問題。ログを見て原因を探します。

? POST を 2 回送ってしまうと、何が起きやすい？
+ 同じデータが 2 件作られる
- 2 回目は自動で無視される
- サーバーが止まる
> POST はべき等ではないので、二度押し対策が必要です。
```
