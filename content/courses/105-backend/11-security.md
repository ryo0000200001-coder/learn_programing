## このレッスンのゴール

- 代表的な攻撃（SQL インジェクション・XSS・CSRF・IDOR など）の名前と仕組みをざっくり説明できる
- AI が書いたバックエンドを、チェックリストで点検できる

これまでのレッスンに出てきたものも含めて、**よくある 10 個** にまとめます。全部を深く理解できなくても、「この観点で見る」と知っているだけで大きく違います。

## ① SQL インジェクション

入力した文字が SQL の命令として解釈されてしまう攻撃（レッスン 7）。

```python
db.execute(f"SELECT * FROM users WHERE name = '{name}'")      # ❌
db.execute("SELECT * FROM users WHERE name = ?", (name,))     # ⭕
```

**守り方**：プレースホルダか ORM を使う。SQL に f-string・`+`・`%` で値を埋め込まない。

## ② 認可漏れ（IDOR）

ログインしていれば、URL の数字を変えるだけで他人のデータが見える・変えられる（レッスン 9）。

```python
task = db.get(Task, task_id)
if task.owner_id != current_user.id:      # ← この確認があるか
    raise HTTPException(404)
```

**守り方**：すべての取得・更新・削除で「その人のデータか」を確かめる。データベースから取るときに `WHERE owner_id = ?` を付けるのが確実。

## ③ パスワードの保存ミス

**守り方**：bcrypt・Argon2 でハッシュ化（レッスン 9）。そのまま・md5 だけ、は NG。ログイン失敗が続いたら待たせる・ロックする。

## ④ 秘密情報の漏えい

API キー・データベースのパスワード・JWT の鍵がコードや Git に入っている。

**守り方**：環境変数や、クラウドの「シークレット管理」に置く。`.env` は `.gitignore` に入れる（AI と開発するコース「秘密情報と環境変数」）。漏れたらすぐ無効化。

## ⑤ XSS（クロスサイトスクリプティング）

利用者が入力した `<script>` などが、他の人の画面でプログラムとして動いてしまう。

**守り方**：表示するときに無害化する（popup2027 の `esc()`）。React などは自動で無害化してくれる。サーバー側では、入力を検証し、レスポンスの `Content-Type` を正しく返す。

## ⑥ CSRF（クロスサイト・リクエスト・フォージェリ）

ログイン中の利用者が、悪いサイトを開いただけで、知らないうちに「送金」などのリクエストを送らされてしまう攻撃。Cookie が自動で付くことを悪用します。

**守り方**：Cookie に `SameSite=Lax`（または `Strict`）を付ける。データを変える操作は GET にしない（レッスン 3）。フレームワークの CSRF 対策（トークン）を使う。

## ⑦ CORS の設定ミス

ブラウザは基本的に、**別のサイト（オリジン）の API の結果を JavaScript で読むこと** を止めています。それを「このサイトからなら許す」と緩める設定が **CORS** です。

```python
app.add_middleware(
    CORSMiddleware,
    allow_origins=["https://myapp.example.com"],   # ⭕ 自分のフロントエンドだけ
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

AI は「CORS エラーが出た」と言われると、`allow_origins=["*"]`（どこからでも OK）にしがちです。**ログインのある API で「どこからでも」は危険** なので、自分のサイトの URL だけを書くようにしましょう。

## ⑧ 呼ばれすぎ（レート制限が無い）

ログイン API を 1 秒に何千回も呼ばれてパスワードを総当たりされる、AI の API を大量に呼ばれて請求が膨らむ、など。

**守り方**：1 人（1 IP）あたりの回数制限をかけ、超えたら `429`。ログイン・登録・メール送信・AI 呼び出しなど、**お金や安全に関わる API は特に**。

## ⑨ 入力の大きさ・種類の制限が無い

1GB の JSON、巨大な画像、想定外のファイル形式（画像のふりをしたプログラム）。

**守り方**：文字数・件数・ファイルサイズに上限を付ける（レッスン 6 の `max_length`）。アップロードはファイルの種類を確かめ、元のファイル名をそのまま使わない。

## ⑩ 古いライブラリ

使っているライブラリに見つかった穴（脆弱性）を、そのままにしている。

**守り方**：`pip list --outdated` や `npm audit`、GitHub の Dependabot で定期的に更新する。AI が提案したライブラリは、本物か・今も更新されているかを確認する（AI と開発するコース「AI の得意・苦手」）。

## チェックリスト（AI のバックエンドを読むとき）

| # | 見るところ | 確認すること |
|---|---|---|
| 1 | SQL を書いている所 | `?`・ORM を使っているか。f-string で埋め込んでいないか |
| 2 | 取得・更新・削除の API | 持ち主・権限の確認があるか |
| 3 | ユーザー登録・ログイン | パスワードをハッシュ化しているか。回数制限があるか |
| 4 | 設定・定数 | 秘密がコードに直書きされていないか |
| 5 | HTML を返す・表示する所 | 無害化しているか |
| 6 | Cookie の設定 | `HttpOnly`・`Secure`・`SameSite` |
| 7 | CORS の設定 | `allow_origins=["*"]` になっていないか |
| 8 | お金・安全に関わる API | 回数制限 |
| 9 | 入力の受け取り | 長さ・サイズ・種類の上限 |
| 10 | `requirements.txt` / `package.json` | 古すぎるもの・聞いたことのないものが無いか |

AI に「このコードを、OWASP の観点でセキュリティレビューして」と頼むのも有効です（**OWASP** は Web のセキュリティの代表的な指針を出している団体です）。ただし最終確認は、このチェックリストで自分の目でも。

```quiz
? 「CORS エラーが出るので allow_origins を ["*"] にしました」と AI が言った。ログインのある API で問題になりうる？
+ なりうる。どのサイトからでも API を使えてしまう
- ならない。CORS はセキュリティに関係ない
> 自分のフロントエンドの URL だけを許可するのが基本です。

? ログイン API にレート制限を付ける主な理由は？
- サーバーの電気代を節約するため
+ パスワードの総当たりを防ぐため
- ログを減らすため
> 短い時間に何度も試せないようにして、総当たり攻撃を防ぎます。

? 次のうち、SQL インジェクションの心配がある書き方は？
- db.execute("SELECT * FROM t WHERE id = ?", (id,))
+ db.execute("SELECT * FROM t WHERE id = " + id)
- session.scalars(select(T).where(T.id == id))
> 文字列をつなげて SQL を作ると、入力が命令として解釈される危険があります。
```
