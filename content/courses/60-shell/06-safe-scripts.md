## このレッスンのゴール

- シェルが「失敗しても止まらない」ことと、`set -euo pipefail` のそれぞれの意味を説明できる
- 空の変数を使った `rm` の危険と、`${VAR:?}` での防ぎ方が分かる
- `trap ... EXIT` と `mktemp` を使った後片付けのコードを読める

## シェルは失敗しても止まらない

```bash
#!/usr/bin/env bash
cd /no/such/dir
echo "ここが実行されると困る（cd に失敗したのに続いている）"
```

```text
safe.sh: line 2: cd: /no/such/dir: No such file or directory
ここが実行されると困る（cd に失敗したのに続いている）
```

`cd` に失敗したのに、**次の行が実行されました**。Python なら例外で止まりますが、シェルは **エラーを表示して、何事も無かったように次へ進みます**。
もし次の行が `rm -rf *` だったら？ **`cd` に失敗して、元の場所のファイルを全部消す** ことになります。

## set -e：失敗したら止まる

```bash
#!/usr/bin/env bash
set -euo pipefail
cd /no/such/dir
echo "ここが実行されると困る"
```

```text
safe.sh: line 3: cd: /no/such/dir: No such file or directory
（ここで止まった。終了コード 1）
```

`set -e` は「**どれかのコマンドが失敗したら、そこでスクリプトを止める**」設定です。Python の「例外が起きたら止まる」に近い動きになります。

⚠️ ただし、`if` の条件や `&&`・`||` の途中で失敗したものは止まりません（失敗するのが前提の書き方なので）。

## set -u：無い変数を使ったら止まる

```bash
set -u
echo "$TYPO_VAR"
# bash: line 1: TYPO_VAR: unbound variable
```

レッスン 2 で、無い変数は **空として扱われる** と学びました。打ち間違いでも黙って空になるので、とても危険です。`set -u` があると、**定義されていない変数を使った時点で止まります**。

わざと「無ければ空」にしたいところは、`"${VAR:-}"`（無ければ空文字）と書きます。

## set -o pipefail：パイプの途中の失敗に気づく

```bash
false | true; echo "pipefail なし: $?"     # 0
set -o pipefail
false | true; echo "pipefail あり: $?"     # 1
```

パイプの終了コードは、初期設定では **最後のコマンドのもの** だけです。途中で失敗しても、最後が成功すれば「成功」になります。たとえば `curl URL | jq .` で、ダウンロードに失敗しても気づけません。
`pipefail` があると、**途中のどれかが失敗したら、パイプ全体が失敗** になります。

## 3 つまとめて

```bash
#!/usr/bin/env bash
set -euo pipefail
```

| 部分 | 意味 |
|---|---|
| `-e` | 失敗したら止まる |
| `-u` | 定義されていない変数を使ったら止まる |
| `-o pipefail` | パイプの途中の失敗も失敗にする |

AI が書くシェルスクリプトの 2 行目によく入っている、**お決まりの 1 行** です。無いスクリプトは、失敗しても気づけない作りになっていると考えて読みます。

## ⚠️ 空の変数と rm

```bash
DIR=""
rm -rf $DIR/*       # → rm -rf /*   （コンピュータ全体を消そうとする！）
```

`DIR` が空だと、`$DIR/*` は `/*` になります。設定の読み込み忘れ・打ち間違い・前の行の失敗など、**変数が空になる理由はいくらでもあります**。実際に、有名なソフトのアンインストール用のスクリプトでこれが起き、利用者のファイルが消えた事件が何度もありました。

（この教材を作っているときも、Claude Code の安全装置が、作業用のフォルダを消そうとした `rm -rf $D` を「変数が空なら `rm -rf /` になる」と止めました。それくらい危ない形です）

### 防ぎ方

```bash
: "${DIR:?DIR が空です}"            # DIR が空なら、メッセージを出して止まる
rm -rf -- "${DIR:?DIR が空です}/build"
```

```text
bash: line 1: DIR: DIR が空です
```

| 書き方 | 意味 |
|---|---|
| `${DIR:?メッセージ}` | DIR が空か未定義なら、メッセージを出して **その場で止まる** |
| `"..."` で囲む | スペースで分かれるのを防ぐ（レッスン 2） |
| `--` | 「ここから後はオプションではなくファイル名」。`-rf` という名前のファイルがあっても安全 |
| `set -u` | 未定義の変数で止まる（ただし **空文字の変数は止まらない** ので、`:?` も必要） |

## trap：終わるときに必ず後片付け

一時的なファイルを作るスクリプトは、**途中で失敗しても** 後片付けをしたいものです。

```bash
#!/usr/bin/env bash
set -euo pipefail
tmp="$(mktemp -d)"
trap 'echo "後片付け: $tmp を消します"; rm -r -- "$tmp"' EXIT
echo "作業中: $tmp"
false                         # ここで失敗する
echo "ここには来ない"
```

```text
作業中: /tmp/tmp.XXXX
後片付け: /tmp/tmp.XXXX を消します     ← 失敗して止まったのに、後片付けは実行された
（終了コード 1）
```

| 部分 | 意味 | Python で言うと |
|---|---|---|
| `mktemp -d` | 他と重ならない名前の一時ディレクトリを作る | `tempfile.mkdtemp()` |
| `trap 'コマンド' EXIT` | スクリプトが **どんな理由で終わっても**、最後にコマンドを実行する | `try: ... finally:` |

`trap '...' INT` なら Ctrl+C で止められたとき、`ERR` なら失敗したとき、のようにきっかけを選べます。

## ShellCheck：シェルスクリプトの検査

**ShellCheck** は、シェルスクリプトのよくある間違い（引用符の付け忘れ、`for f in $(ls)`、`[ $x = y ]` など）を指摘してくれる道具です。VS Code の拡張機能もあります。

```text
SC2086: Double quote to prevent globbing and word splitting.
（ダブルクォートで囲んで、単語分割とグロブを防いでください）
```

この警告が出たら、レッスン 2 の「変数は `"$var"`」の話です。AI のシェルスクリプトを動かす前に通すと安心です。

## AI のコードではこう出てくる

| 見かけたら | 判定 |
|---|---|
| `set -euo pipefail` が無い | ⚠️ 失敗しても続く。特に `cd` の後に `rm` があるなら危険 |
| `cd "$dir"` の後に `rm` / `mv` | `set -e` か `cd "$dir" \|\| exit 1` があるか |
| `rm -rf $VAR/` / `rm -rf "$VAR"/*` | ⚠️⚠️ VAR が空だと `/` を消す。`${VAR:?}` に |
| `trap 'rm -rf "$tmp"' EXIT` | ✅ 後片付け |
| `/tmp/myapp.tmp` のような決め打ちの一時ファイル | 同時に動かすとぶつかる。`mktemp` |
| `curl ... \| sh` に `set -o pipefail` が無い | ダウンロードに失敗しても、途中までのスクリプトが実行されうる |

```quiz
? `set -e` が無いスクリプトで、`cd build` が失敗した。次の行の `rm -rf *` はどうなる？
- cd が失敗したので、rm も自動で止まる
+ 実行される。元のディレクトリのファイルが消えてしまう
- エラーになって何も消えない
> シェルは失敗しても次の行へ進みます。`set -e` を付けるか、`cd build || exit 1` のように失敗したら止まるようにします。

? `rm -rf "${BUILD_DIR:?}/dist"` の `:?` の役割は？
+ BUILD_DIR が空か未定義なら、rm を実行せずにその場で止める
- BUILD_DIR が空なら、今のディレクトリを使う
- BUILD_DIR の中身を確認する画面を出す
> 変数が空だと `/dist` を消すことになります。`:?` があれば、空のときはエラーで止まります。

? `trap 'rm -r -- "$tmp"' EXIT` の意味は？
- 今すぐ tmp を消す
+ スクリプトが失敗しても成功しても、終わるときに tmp を消す
- tmp が消されないように守る
> EXIT のきっかけで、終わり方に関係なく後片付けが実行されます。Python の `finally` に当たります。
```
