## このレッスンのゴール

- シェルの変数を作る・使う書き方を読める（`=` の前後にスペースを入れない理由も）
- `"..."` と `'...'` の違いが分かる
- **変数を `"$var"` と引用符で囲む理由** を、実際の例で説明できる

## 変数を作る・使う

```bash
name="Ryo"          # 作る：= の前後にスペースを入れない
echo "$name"        # 使う：前に $ を付ける
```

⚠️ Python の癖で `name = "Ryo"` と書くと、こうなります。

```text
bash: name: command not found
```

シェルは **スペースで区切って** 読むので、`name = "Ryo"` は「`name` というコマンドに、`=` と `Ryo` を渡して実行」と解釈されます。**`=` の前後にスペースを入れない** のがシェルの決まりです。

### 変数名の区切り

```bash
name="Ryo"
echo "${name}san"     # Ryosan
echo "[$namesan]"     # []   ← namesan という別の（空の）変数だと思われた
```

変数のすぐ後ろに文字が続くときは、`${name}` と波かっこで囲みます。⚠️ 存在しない変数を使っても **エラーにならず、空になる** のがシェルの怖いところです（レッスン 6 で防ぎ方を学びます）。

## ダブルクォートとシングルクォート

```bash
name="Ryo"
echo "こんにちは、$name さん"     # こんにちは、Ryo さん
echo 'こんにちは、$name さん'     # こんにちは、$name さん
```

| 引用符 | 中の `$name`・`$(...)` | 使いどころ |
|---|---|---|
| `"..."`（ダブル） | **置き換えられる** | ふつうはこちら。変数を使う文字列 |
| `'...'`（シングル） | **そのまま**（置き換えない） | `$` などをそのまま書きたいとき（正規表現、他のプログラムに渡すコード） |

Python で言うと、`"..."` は f 文字列 `f"...{name}..."`、`'...'` は普通の文字列 `"...{name}..."` に近いです。

## 引用符を付けないとどうなるか

いちばん大事なところです。名前にスペースが入ったファイルで試します。

```bash
f="my file.txt"

ls $f
# ls: cannot access 'my': No such file or directory
# ls: cannot access 'file.txt': No such file or directory

ls "$f"
# my file.txt
```

引用符の無い `$f` は、**中のスペースで 2 つに分かれて**、`ls my file.txt`（`my` と `file.txt` の 2 つ）として実行されました。これを **単語分割** と呼びます。

Python で言うと、こんな違いです。

```python
f = "my file.txt"
ls(*f.split())   # $f    → ls("my", "file.txt")
ls(f)            # "$f"  → ls("my file.txt")
```

ファイル名だけでなく、ユーザーの入力・パス・コマンドの出力など、**スペースが入るかもしれないものは全部** 同じ問題が起きます。

**変数は、いつも `"$var"` とダブルクォートで囲む**。これがシェルスクリプトを読むときの最大のチェックポイントです。

| 書き方 | 判定 |
|---|---|
| `cp $src $dest` | ⚠️ スペースを含むパスで壊れる |
| `cp "$src" "$dest"` | ✅ |
| `rm -rf $DIR/build` | ⚠️⚠️ スペースで分かれて、別の場所を消す可能性（レッスン 6） |
| `if [ $x = "y" ]` | ⚠️ x が空だと `[: =: unary operator expected` というエラー（レッスン 3） |

## コマンドの出力と計算

```bash
today="$(date +%Y-%m-%d)"       # コマンドの出力を変数に
count="$(wc -l < notes.txt)"    # ファイルの行数を変数に
total=$((3 + 4 * 2))            # 計算（整数だけ）→ 11
```

| 書き方 | 意味 |
|---|---|
| `$(コマンド)` | コマンドを実行して、出力を文字として使う |
| `` `コマンド` ``（バッククォート） | 同じ意味の古い書き方 |
| `$((式))` | 整数の計算。小数は扱えない（`$((7 / 2))` は 3） |

## シェルの変数と環境変数

```bash
x=5
bash -c 'echo "子のシェル: [$x]"'      # 子のシェル: []
export x
bash -c 'echo "export の後: [$x]"'     # export の後: [5]
```

| | シェルの変数 | 環境変数 |
|---|---|---|
| 作り方 | `x=5` | `export x=5` |
| 見える範囲 | **そのシェルの中だけ** | そのシェルから **起動したプログラムにも** 渡される |
| 例 | スクリプトの中の作業用の値 | `PATH`、`HOME`、`DATABASE_URL`（公開とクラウドのコースのレッスン 4） |

Python のプログラムから `os.environ["DATABASE_URL"]` で読めるのは、**export された環境変数だけ** です。`.env` を読み込むのに `export $(cat .env | xargs)` のような書き方を見かけるのはこのためです（スペースや `#` を含む値で壊れるので、`set -a; source .env; set +a` の方が安全です）。

1 つのコマンドにだけ渡したいときは、前に書きます。

```bash
APP_ENV=production python main.py    # この 1 回だけ APP_ENV を渡す
```

## ${...} の便利な書き方

```bash
echo "${undefined:-default}"          # default   （空なら代わりの値）

name="photo.final.jpg"
echo "${#name}"                       # 15        （文字数）
echo "${name%.*}"                     # photo.final （最後の . から後ろを消す）
echo "${name##*.}"                    # jpg       （最後の . まで消す ＝ 拡張子）
echo "${name/final/old}"              # photo.old.jpg （置き換え）
```

| 書き方 | 意味 | Python で言うと |
|---|---|---|
| `${x:-値}` | x が空なら「値」 | `x or "値"` |
| `${x:?メッセージ}` | x が空ならエラーで止める（レッスン 6） | `if not x: raise ...` |
| `${#x}` | 文字数 | `len(x)` |
| `${x%.*}` | 後ろから最短で `.〜` を消す | `x.rsplit(".", 1)[0]` |
| `${x##*.}` | 前から最長で `〜.` を消す | `x.rsplit(".", 1)[-1]` |
| `${x/古/新}` | 最初の 1 つを置き換え | `x.replace("古", "新", 1)` |

## AI のコードではこう出てくる

| 見かけたら | チェック |
|---|---|
| `VAR = value` | ⚠️ スペースがあるとコマンドとして実行される |
| `$var` が引用符なしで使われている | ⚠️ スペースを含む値で壊れる。`"$var"` に |
| `'$HOME/app'` | シングルクォートなので `$HOME` が置き換わらない。意図どおりか |
| `PORT="${PORT:-8000}"` | 環境変数 PORT が無ければ 8000（よくある形） |
| `export $(cat .env \| xargs)` | 値にスペースや `#` があると壊れる |

```quiz
? シェルで変数を作る正しい書き方は？
- `name = "Ryo"`
+ `name="Ryo"`
- `$name = "Ryo"`
> `=` の前後にスペースがあると、`name` というコマンドの実行だと解釈されます（`name: command not found`）。

? `f="my file.txt"` のとき、`ls $f` が 2 つのエラーを出した理由は？
+ 引用符が無いので、値がスペースで分かれて「my」と「file.txt」の 2 つとして渡されたから
- ls はスペースを含むファイルを扱えないから
- 変数 f が空だから
> 引用符の無い変数は単語分割されます。`ls "$f"` と書けば、1 つのファイル名として渡されます。

? `echo '$HOME'` の出力は？
- ホームディレクトリのパス（`/home/ryo` など）
+ `$HOME` という文字そのまま
- 何も表示されない
> シングルクォートの中では変数が置き換えられません。置き換えたいならダブルクォート `"$HOME"` を使います。
```
