## このレッスンのゴール

- 標準出力・標準エラーと、`>`・`2>`・`2>&1`・`/dev/null` の意味を説明できる
- `|`（パイプ）でつないだ長いコマンドを、左から順に読める
- `grep`・`awk`・`sort | uniq -c` などのテキスト処理の定番の形が分かる

ターミナルと Git のコースのレッスン 2 で、`|` と `>` を簡単に紹介しました。ここでは、AI がよく出してくる **1 行の集計コマンド** を読めるようにします。

## 2 つの出力：標準出力と標準エラー

コマンドの出力には、2 つの通り道があります。

| 名前 | 番号 | 流れるもの | Python で言うと |
|---|---|---|---|
| **標準出力**（stdout） | 1 | 普通の結果 | `print(...)` |
| **標準エラー**（stderr） | 2 | エラーや進み具合のメッセージ | `print(..., file=sys.stderr)` |
| 標準入力（stdin） | 0 | コマンドへの入力 | `input()`、`sys.stdin` |

画面ではどちらも同じように見えますが、**別々に扱えます**。

```bash
ls nope > out.txt 2> err.txt
# out.txt は空、err.txt に「ls: cannot access 'nope': No such file or directory」
```

| 書き方 | 意味 |
|---|---|
| `> file` | 標準出力をファイルへ（上書き） |
| `>> file` | 標準出力をファイルの末尾へ |
| `2> file` | 標準エラーをファイルへ |
| `> file 2>&1` | **両方** を同じファイルへ（「2 番を 1 番と同じ所へ」） |
| `> /dev/null` | 捨てる（`/dev/null` は何でも吸い込んで消す特別な場所） |
| `2> /dev/null` | エラーだけ捨てる |
| `< file` | ファイルを標準入力にする |
| `>&2` | 自分の出力を標準エラーへ（レッスン 3 のスクリプトのエラーメッセージ） |

⚠️ `2>&1` は **書く順番** が大事です。`> file 2>&1` は両方がファイルへ行きますが、`2>&1 > file` は、エラーは画面に残ります。

AI のコードの `command -v jq > /dev/null 2>&1` は、「出力もエラーも全部捨てて、**終了コード（あるかどうか）だけ** を使う」という意味です。

## パイプ：左の出力を右の入力に

```bash
grep " 500 " access.log | wc -l
```

`|` は、**左のコマンドの標準出力を、右のコマンドの標準入力につなぎます**。小さなコマンドをつないで、大きな処理を作るのがシェルの考え方です。

Python で言うと、関数の結果を次の関数に渡し続けるのと同じです。

```python
len([line for line in open("access.log") if " 500 " in line])
```

## 例のログ

Web サーバーのアクセスログ（公開とクラウドのコースのレッスン 8）です。

```text
2026-11-23T09:00:01 GET /tasks 200 12ms
2026-11-23T09:00:05 POST /orders 500 40ms
2026-11-23T09:01:10 GET /tasks 200 9ms
2026-11-23T09:02:00 GET /users/3 404 5ms
2026-11-23T09:03:30 POST /orders 201 35ms
2026-11-23T09:04:12 GET /tasks 200 11ms
2026-11-23T09:05:00 POST /orders 500 52ms
```

空白で区切ると、1 列目が時刻、2 列目がメソッド、3 列目がパス、4 列目がステータス、5 列目が時間です。

## grep：探す

```bash
grep " 500 " access.log | wc -l      # 2   （500 エラーの行数）
```

| オプション | 意味 |
|---|---|
| `-i` | 大文字小文字を区別しない |
| `-v` | 当てはまら **ない** 行 |
| `-c` | 行数だけ |
| `-n` | 行番号も |
| `-r` | ディレクトリの中を全部 |
| `-q` | 何も出さず、終了コードだけ（レッスン 3） |
| `-E` | 正規表現（`grep -E "500\|404"`） |

## awk・cut：列を取り出す

```bash
cut -d' ' -f2,3 access.log | head -3
# GET /tasks
# POST /orders
# GET /tasks

awk '{print $3}' access.log           # 3 列目（パス）だけ
```

| コマンド | 意味 |
|---|---|
| `cut -d' ' -f2,3` | 区切り（`-d`）を空白にして、2・3 列目（`-f`） |
| `awk '{print $3}'` | 空白で区切った 3 列目。⚠️ ここの `$3` はシェルの引数ではなく **awk の列**。だからシングルクォートで囲む（レッスン 2） |

awk は小さなプログラミング言語で、計算もできます。

```bash
awk '{gsub("ms", "", $5); s += $5} END {print "平均", s/NR, "ms"}' access.log
# 平均 23.4286 ms
```

「5 列目から ms を消して足していき、最後（`END`）に行数（`NR`）で割る」。Python で言うと、こうです。

```python
times = [int(line.split()[4].removesuffix("ms")) for line in open("access.log")]
print("平均", sum(times) / len(times), "ms")
```

## sort | uniq -c：数える定番

```bash
awk '{print $3}' access.log | sort | uniq -c | sort -rn
```

```text
      3 /tasks
      3 /orders
      1 /users/3
```

| 段階 | 出力 |
|---|---|
| `awk '{print $3}'` | パスだけを 7 行 |
| `sort` | 同じものが隣り合うように並べる |
| `uniq -c` | **隣り合った** 同じ行をまとめて、数を付ける |
| `sort -rn` | 数（`-n`）の大きい順（`-r`）に並べる |

**「何が何回出てきたか」のランキング** です。`uniq` は隣り合ったものしかまとめないので、先に `sort` するのがポイントです。Python の `collections.Counter(paths).most_common()`、SQL の `GROUP BY ... ORDER BY COUNT(*) DESC`（SQL コースのレッスン 3）と同じことをしています。

## sed：置き換える

```bash
sed 's/ms$/ ミリ秒/' access.log | tail -1
# 2026-11-23T09:05:00 POST /orders 500 52 ミリ秒
```

`s/探す/置き換え/` は「行の中の最初の 1 つを置き換え」、`s/.../.../g` は全部です。`$` は「行の終わり」（正規表現）。

⚠️ `sed -i` は **ファイルそのものを書き換えます**（Mac では `sed -i ''` と書く必要があるなど、OS で書き方が違う）。AI が `sed -i` を出してきたら、先に `-i` 無しで結果を確かめると安全です。

## その他の定番

| コマンド | 意味 | 例 |
|---|---|---|
| `wc -l` | 行数 | `wc -l < file` |
| `head -n 5` / `tail -n 5` | 先頭／末尾の 5 行 | |
| `tail -f app.log` | 追加される行を流し続けて見る（Ctrl+C で終わる） | ログの監視 |
| `xargs` | 入力の各行を、次のコマンドの引数にする | `printf 'a.txt\nb.txt\n' \| xargs -I{} echo "処理: {}"` |
| `tee` | 画面にも出しつつファイルにも書く | `make 2>&1 \| tee build.log` |
| `jq` | JSON を扱う | `curl ... \| jq '.orders \| length'` |

```bash
echo '{"name":"Ryo","orders":[{"id":1},{"id":2}]}' | jq '.orders | length'
# 2
```

`jq` は、API の返事（JSON）から値を取り出すときによく使われます（`.name` で name、`.orders[0].id` で最初の注文の id）。

## AI のコードではこう出てくる

| 見かけたら | 読み方・チェック |
|---|---|
| `... \| sort \| uniq -c \| sort -rn \| head` | 何が何回出たかの上位 |
| `> /dev/null 2>&1` | 出力を全部捨てて、成功・失敗だけを見る |
| `2>/dev/null` がたくさん | ⚠️ エラーを隠している。失敗に気づけないかも |
| `grep ... \| awk '{print $2}' \| xargs kill` | 見つけたプロセスの番号を取り出して止める。⚠️ 何に当たるか、先に `grep` だけ実行して確かめる |
| `sed -i 's/.../.../g' *.py` | ⚠️ たくさんのファイルを直接書き換える。Git でコミットしてから |
| `curl -s URL \| jq -r '.token'` | API の返事から値を取り出す。`-r` は引用符なしの文字で |

```quiz
? `python app.py > app.log 2>&1` の意味は？
- 標準出力だけを app.log に書き、エラーは画面に出す
+ 標準出力と標準エラーの両方を app.log に書く
- app.log の内容を python app.py に渡す
> `2>&1` は「2 番（標準エラー）を 1 番（標準出力）と同じ所へ」です。1 番が app.log なので、両方がファイルに入ります。

? `awk '{print $3}' access.log | sort | uniq -c` で、`sort` が必要な理由は？
- 結果をきれいに見せるため
+ `uniq` は隣り合った同じ行しかまとめないので、先に同じものを並べる必要があるから
- awk の出力は並べ替えないと読めないから
> sort で同じパスを隣に集めてから、uniq -c で数えます。sort が無いと、離れた同じ行が別々に数えられます。

? `awk '{print $3}'` をシングルクォートで囲む理由は？
+ `$3` をシェルの引数として置き換えずに、そのまま awk に渡すため
- awk の命令は必ずシングルクォートで書く決まりだから
- ダブルクォートでは日本語が使えないから
> ダブルクォートだと、シェルが先に `$3`（スクリプトの 3 つ目の引数）に置き換えてしまいます。awk の列の `$3` として渡すために、シングルクォートで囲みます。
```
