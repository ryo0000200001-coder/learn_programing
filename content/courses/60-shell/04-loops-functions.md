## このレッスンのゴール

- `for` と `while read` の繰り返しを読める
- シェルの関数と `local` を読める
- 引数の `$1`・`$#`・`"$@"` の意味が分かり、`"$@"` と `$@` の違いを説明できる

## for：並んだものを順番に

```bash
for name in Ryo Hana "Ken Sato"; do
  echo "こんにちは、${name} さん"
done
```

```text
こんにちは、Ryo さん
こんにちは、Hana さん
こんにちは、Ken Sato さん
```

| 部分 | 意味 | Python で言うと |
|---|---|---|
| `for name in A B C; do` | A・B・C を順番に name に入れて | `for name in ["A", "B", "C"]:` |
| `done` | 繰り返しの終わり | （インデントの終わり） |

並べたものは **スペースで区切られる** ので、`"Ken Sato"` のようにスペースを含むものは引用符で 1 つにまとめます。

### ファイルを順番に

```bash
for f in *.txt; do
  echo "txt: $f"
done
```

```text
txt: my file.txt
txt: notes.txt
```

`*.txt` は「.txt で終わるファイル全部」に置き換わります（**グロブ**）。スペースを含む「my file.txt」も、ちゃんと 1 つとして扱われています。Python の `for f in Path(".").glob("*.txt"):` です。

⚠️ 当てはまるファイルが 1 つも無いと、`*.txt` という **文字そのもの** が 1 回だけ入ってきます。`[ -e "$f" ] || continue` で飛ばすコードをよく見るのはこのためです。

⚠️ `for f in $(ls)` という書き方も見かけますが、**スペースを含むファイル名で分かれてしまう** ので、グロブ（`for f in *`）を使うのが正解です（レッスン 7 で実例を見ます）。

### 数で繰り返す

```bash
for i in 1 2 3; do echo "$i"; done
for i in $(seq 1 5); do echo "$i"; done        # 1〜5
for ((i = 0; i < 3; i++)); do echo "$i"; done   # C 言語風。0, 1, 2
```

## while read：1 行ずつ読む

```bash
i=0
while read -r line; do
  i=$((i + 1))
  echo "$i: $line"
done < notes.txt
```

```text
1: a
2: b
3: c
```

| 部分 | 意味 |
|---|---|
| `while コマンド; do ... done` | コマンドが成功している間くり返す |
| `read -r line` | 1 行読んで line に入れる。読めなくなったら（ファイルの終わり）失敗 → 繰り返しが終わる |
| `-r` | `\` を特別扱いしない（付けておくのが定番） |
| `done < notes.txt` | 繰り返し全体の入力を notes.txt にする（レッスン 5） |

Python の `for line in open("notes.txt"):` に当たります。コマンドの出力を 1 行ずつ処理するなら `コマンド | while read -r line; do ... done` と書きます。

## 関数

```bash
greet() {
  local who="$1"
  echo "こんにちは、${who} さん"
}

greet "Ryo"     # こんにちは、Ryo さん
```

| 部分 | 意味 | Python で言うと |
|---|---|---|
| `greet() { ... }` | 関数の定義 | `def greet(who):` |
| `$1`, `$2` … | 関数に渡された 1 つ目、2 つ目の値 | 引数 |
| `local who=...` | **この関数の中だけ** の変数 | 関数の中のローカル変数 |
| `greet "Ryo"` | 呼び出し。**かっこも `,` も使わない** | `greet("Ryo")` |

⚠️ `local` を付けないと、関数の中で作った変数は **スクリプト全体で共有** されます（Python と逆）。同じ名前の変数を知らないうちに上書きする原因になります。

関数の「戻り値」は、2 つの方法があります。

| やりたいこと | 書き方 |
|---|---|
| 文字を返す | 関数の中で `echo` し、呼ぶ側で `result="$(greet Ryo)"` と受け取る |
| 成功・失敗を返す | `return 0` / `return 1`（終了コード。0〜255 の数だけ） |

## スクリプトの引数

スクリプトを実行するときに渡した値は、こう受け取ります。

```bash
./loop.sh start "a b"
```

| 書き方 | 中身 | Python で言うと |
|---|---|---|
| `$0` | スクリプトの名前（`./loop.sh`） | `sys.argv[0]` |
| `$1` | 1 つ目（`start`） | `sys.argv[1]` |
| `$2` | 2 つ目（`a b`） | `sys.argv[2]` |
| `$#` | 引数の数（`2`） | `len(sys.argv) - 1` |
| `"$@"` | 全部の引数（1 つずつ別々に） | `sys.argv[1:]` |

### "$@" と $@ の違い

```bash
for arg in "$@"; do echo "[\"\$@\"] $arg"; done
for arg in $@;   do echo "[\$@] $arg"; done
```

```text
["$@"] start
["$@"] a b          ← 「a b」が 1 つのまま
[$@] start
[$@] a              ← スペースで分かれてしまった
[$@] b
```

引用符を付けた `"$@"` は、**渡されたとおりの区切りを守ります**。付けない `$@` は、レッスン 2 の単語分割が起きます。**引数をそのまま別のコマンドに渡すときは、必ず `"$@"`** です。

```bash
#!/usr/bin/env bash
# 引数を全部そのまま pytest に渡すスクリプト
exec python -m pytest "$@"
```

`$*` という似た書き方もありますが、引数を 1 つの文字列にまとめてしまうので、ほとんどの場合 `"$@"` が正解です。

## AI のコードではこう出てくる

| 見かけたら | チェック |
|---|---|
| `for f in $(ls *.csv)` | ⚠️ スペースを含むファイル名で壊れる。`for f in *.csv` |
| `for f in *.log; do` の中に `[ -e "$f" ] \|\| continue` | ✅ ファイルが 1 つも無いときの対策 |
| `cat file \| while read line` | `-r` が無いと `\` が消える。`while read -r line; do ... done < file` が定番 |
| 関数の中で `local` を使っていない | ⚠️ スクリプト全体の変数を上書きしていないか |
| `python app.py $@` | ⚠️ `"$@"` に |
| `shift` | 引数を 1 つずらす（`$2` が `$1` になる）。オプションを順に読むときに使う |

```quiz
? `./run.sh "hello world" test` を実行したとき、スクリプトの中の `$#` と `$1` は？
- `$#` は 3、`$1` は `hello`
+ `$#` は 2、`$1` は `hello world`
- `$#` は 2、`$1` は `./run.sh`
> 引用符で囲んだ「hello world」は 1 つの引数です。`$0` がスクリプト名、`$1` が 1 つ目の引数です。

? 受け取った引数を、区切りを変えずにそのまま別のコマンドに渡す書き方は？
- `$@`
- `$*`
+ `"$@"`
> 引用符を付けた `"$@"` だけが、元の引数の区切りを守ります。`$@` だとスペースで分かれます。

? 関数の中の変数に `local` を付ける理由は？
- 処理が速くなるから
+ 付けないと、スクリプト全体の同じ名前の変数を上書きしてしまうから
- 付けないと関数が動かないから
> シェルでは、関数の中の変数も初期設定ではスクリプト全体で共有されます。`local` でその関数の中だけにします。
```
